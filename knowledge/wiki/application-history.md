# Определения: история решений и заявок

- **История решения** — поток событий по заявке, а не справочник с одной строкой
  на заявку. У одной заявки может быть несколько событий смены решения.
- **Срез знания** — состояние, которое можно было увидеть в хранилище
  к указанному моменту.

## Правила работы с историей

- Сначала фиксируется время знания, затем фильтруются события, затем выбирается
  последняя запись в документированном порядке, и только после этого проверяется
  кардинальность результата.
- «Последнее» событие выбирается документированным порядком; сортировка
  по алфавиту статуса не является порядком времени и не применяется.
- При выборе между событиями с равным бизнес-временем используется
  документированный тай-брейк.
- После выбора среза проверяется уникальность `application_id` и сохранение
  числа заявок при `LEFT JOIN`.
- Режим пересчёта на то же бизнес-время фильтрует бизнес-время по той же границе,
  что и исторический срез, но не ограничивает время загрузки.
- При анализе и сохранении результатов исходные данные не изменяются.
