# Оценка антифрода: метки, precision, recall, coverage

## Срез меток

Для исторической оценки берётся последняя строка `fraud_labels` с `recorded_at < T` по заявке; при равном `recorded_at` — `label_id DESC`. Метки из будущего не применяются. Текущий снимок может включать поздние исправления и для исторической оценки не годится.

## Классификация

- TP — срабатывание правила у заявки с `confirmed_fraud`.
- FP — срабатывание у заявки с `legitimate`.
- `unknown` — метки нет или она не определена на дату; **не** входит в TP + FP, **не** считается `legitimate` и **не** подменяется нулём.

## Формулы

- `precision = TP / (TP + FP)`; при нулевом знаменателе precision **не определена**, а не ноль.
- `recall` — по размеченной части когорты: TP / число `confirmed_fraud` среди всех заявок с известной меткой.
- `coverage` = число уникальных заявок со срабатыванием / число реальных заявок когорты.

Дополнительно показывать долю размеченных и абсолютные размеры групп, включая `unknown` отдельной строкой. Срабатывание правила не равно фроду и не равно отказу.

## Порог достаточности

Утверждённых порогов достаточности выборки нет. По малой учебной выборке нельзя делать вывод о внедрении правила.

## Наблюдавшийся случай

На `T = 2026-10-03 00:00:00 UTC` известно 0 меток: все `recorded_at` не раньше 2026-10-03 09:00, а исправление A001 на `legitimate` внесено 2026-10-06 (`investigation_corrected`). Поэтому precision/recall не считались: исход неизвестен, а не добросовестен. Равных `recorded_at` по одной заявке в данных не было, тай-брейк фактически не срабатывал.

## SLA разметки

Утверждённого SLA и владельца нет. Заметки «D+3» и «D+5» — неутверждённые оценки, не правило и не срок; подставлять их как утверждённый SLA нельзя. Подробнее — [unknowns-and-source-status.md](unknowns-and-source-status.md).
