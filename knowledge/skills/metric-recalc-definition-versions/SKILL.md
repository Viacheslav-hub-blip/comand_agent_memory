# Пересчёт бизнес-метрики на историческом срезе по версиям определения

## Когда применять

Нужно посчитать заявочный или событийный агрегат «как он был известен» на дату `T`, а определение метрики имеет несколько версий с датами действия, и/или требуется воспроизвести прежний отчёт. Типичный результат: значения показателя по каждой версии с явными числителем, знаменателем, периодом когорты и датой среза.

## Вход

- Текущая и архивная версии определения с датами действия; словарь данных или схема.
- Таблицы сущностей и их истории (`applications`, `decision_events`, `payments`, `fraud_labels`, `rule_hits` в проекте «Север»).
- Параметры: границы когорты по времени регистрации (нижняя включена, верхняя исключена), дата среза `T`, выбираемая версия определения, при необходимости отдельный денежный интервал.
- Правило выбора последней записи истории и признак тестовых записей (`is_test`).
- Каталог результата (в проекте — отдельный `outputs/<tag>/`).

## Алгоритм

1. Прочитать действующую версию определения и зафиксировать её правила; архивную версию читать, когда нужен воспроизводимый старый отчёт или сравнение версий. Зафиксировать различия: фильтры, числитель, знаменатель, правила среза, наличие парной метрики.
2. Задать параметрами: период когорты, `T`, версию, денежный интервал. Не вшивать текущие даты и суммы в текст запроса.
3. Построить снимок состояния на `T`: отобрать записи истории с `occurred_at < T` **и** `loaded_at < T`; внутри каждой сущности упорядочить по `occurred_at DESC, event_id DESC`; взять первую строку. Для меток — `recorded_at < T`, тай-брейк `label_id DESC`.
4. Присоединить снимок к набору сущностей через `LEFT JOIN`, сохраняя ровно одну строку на сущность; отсутствие записи оставить отдельным состоянием «неизвестно».
5. Для каждой версии применить её правила и вычислить числитель и знаменатель. По v2 (`is_test=1` исключается из числителя и знаменателя) в знаменателе `approval_rate` остаются все реальные заявки когорты, включая `cancelled`, `manual_review` и `unknown`; по v1 тестовые заявки входят и в числитель, и в знаменатель.
6. При запросе посчитать парную метрику отдельно: `final_decision_approval_rate = approved / (approved + rejected)` без тестовых, на том же срезе, и обозначить её как другую метрику.
7. Сохранить снимок, сводку метрик и краткие выводы с версиями, числителями, знаменателями, периодом и датой среза; денежные показатели вывести отдельными строками.

## Проверка

- Ровно одна строка состояния на сущность; число строк после соединения равно числу сущностей.
- Среди решающих записей нет событий с `occurred_at >= T` и нет записей с `loaded_at >= T`.
- При равном `occurred_at` выбор определён тай-брейком, а не порядком строк.
- Фильтр `is_test` соответствует выбранной версии определения.
- Знаменатель `approval_rate` не равен знаменателю финальных решений, если есть незавершённые заявки.
- Негативный контроль: если в данных есть записи, отсекаемые ключевым фильтром (например, `loaded_at >= T`), проверь, что расчёт без этого фильтра меняет хотя бы одно состояние; при отсутствии таких записей зафиксируй, что контроль неприменим, вместо вывода о корректности.

## Условные действия

- **Событие имеет `occurred_at < T`, но `loaded_at >= T`** → исключить из среза и показать заявку, на которую это повлияло.
- **Одинаковый `occurred_at` у двух событий** → выбрать больший `event_id` и подтвердить выбор в отчёте.
- **Определение изменило фильтр `is_test` или знаменатель** → вычислить обе версии, старую пометить как архив, текущую — как действующую.
- **Запрошен `final_decision_approval_rate`** → показать отдельной строкой с собственным знаменателем, не подменяя `approval_rate`.
- **Запрошен разовый формат слайда** → сделать компактную строку и примечание, не меняя обычный формат отчётов.
- **В документах нет утверждённого SLA или владельца процесса** → указать, что правило не установлено, и не подставлять неутверждённую заметку как срок.
- **Нужна воспроизводимость для другой когорты** → вынести параметры и прогнать шаблон с другими значениями без правки SQL.

## Результат и завершение

Получены состояния на срез, значения метрик по версиям, сводка с числителем, знаменателем, периодом когорты, датой среза и версией определения; проверки пройдены; архивный результат отделён от действующего. Дополнительные артефакты (раннер, БД, построчные выгрузки, файлы для слайда) готовятся только по запросу. Работа завершена, когда запрошенные числа и оговорки выданы, а неизвестное обозначено как неустановленное.
