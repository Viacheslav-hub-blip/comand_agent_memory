# Case: отсутствие строки — неизвестность, а не отрицательный класс

## Узнаваемая ситуация

По сущности нет строк в справочнике заключений или платежей, либо исторический срез меток на дату `T` оказывается пустым. Возникает соблазн прочитать это как «добросовестный» или «нет платежей». Снимок ограничен по времени, поэтому «нет строки» означает «нет в этом снимке». Триггер второго вида: точность правила хотят посчитать по текущему снимку меток, включающему поздние исправления.

## Исторический пример 1 — пустой срез меток (нулевой знаменатель)

- **Задача и условия:** дата знания `T = 2026-10-03 00:00:00 UTC`; таблица `fraud_labels` с `recorded_at` и правилом «последняя версия до `T`, тай-брейк `label_id DESC`»; когорта заявок 2026-10-01 — 2026-10-03.
- **Что сделали:** построили срез меток по `recorded_at < T` и посчитали, сколько меток известно; сопоставили с `rule_hits` и текущим снимком меток.
- **Как проверили:** срез дал 0 записей — все `recorded_at` не раньше 2026-10-03 09:00; A001 в текущем снимке помечена `legitimate` только 2026-10-06 (`investigation_corrected`). Равных `recorded_at` по одной заявке в данных нет, поэтому тай-брейк по `label_id` фактически не срабатывал.
- **Что получили:** показатели precision/recall по этой когорте не считались — исход неизвестен, а не добросовестен. Срабатывания правила остались без подтверждённых исходов; доля размеченных равна нулю.

## Исторический пример 2 — A006 без меток и платежей, горизонт снимка

- **Задача и условия:** в системе «Заявки» A006 не имеет строк в `fraud_labels` и `payments`; словарь: отсутствие строки — неизвестный исход, а не `legitimate`.
- **Что сделали:** разделили три состояния — есть заключение, неизвестно (нет строки), отсутствует навсегда (по снимку не устанавливается); проверили границы наблюдения по каждому источнику.
- **Как проверили:** посчитали строки по A006 (0 меток, 0 платежей); зафиксировали максимальные наблюдаемые даты: `decision_events` до 2026-10-04 08:01, `fraud_labels` до 2026-10-06 12:00 — любое «нет» ограничено горизонтом снимка. Проверили ревизию: по A001 первичное `confirmed_fraud` (2026-10-03 09:00) переписано на `legitimate` (2026-10-06 12:00).
- **Что получили:** A006 отнесена к `unknown`, не к `legitimate`; её денежное движение описано как «нет проведённых событий в снимке», не как ноль и не как «ждёт загрузки». Отмечено, что появление заключения не равно окончательному заключению.

## Условия переноса

Неизвестный исход — отдельное состояние, его нельзя схлопывать в `legitimate`. Текущий снимок с поздними исправлениями нельзя подставлять в историческую оценку; отсутствие строки не означает `legitimate`. При нулевом знаменателе precision не определена, а не ноль, и по малой выборке вывод о внедрении правила не делается. При отчётах о покрытии различать отсутствие, неизвестность и отрицательный класс; фиксировать горизонт наблюдения; учитывать ревизии заключений при выборе версии по `recorded_at`. Условие переноса — документированное значение отсутствия строки.
