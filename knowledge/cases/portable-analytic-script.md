# Воспроизводимый аналитический скрипт: относительные пути и явная кодировка вывода

- Ситуация: аналитический скрипт содержит жёстко заданный абсолютный путь к данным
  и при переносе или повторном запуске ломается; отдельно — вывод скрипта,
  перенаправленный в файл в Windows `cmd.exe`, затем не читается как UTF-8.
- Причина: абсолютный путь привязан к одной машине и каталогу, а не к структуре
  проекта. Перенаправленный вывод пишется в кодовую страницу консоли (cp866/cp1251),
  а не в UTF-8.
- Решение: вычислять путь к входам относительно расположения скрипта
  (`__file__`, `os.path.dirname`), результат писать в согласованную папку вывода;
  внешние данные передавать явным параметром или конфигом. Для вывода —
  `subprocess.run(capture_output=True, env=PYTHONIOENCODING='utf-8')`
  и запись `res.stdout.decode('utf-8')` в файл явно; сложные скрипты писать файлом,
  а не `python -c` (в `cmd.exe` ломаются кавычки и `%`).
- Проверка: финальный скрипт запустился из своего каталога, нашёл входные CSV,
  записал таблицу в папку результата; файл вывода читается как UTF-8, кириллица
  корректна.
- Границы: относительные пути подходят при стабильном взаимном расположении входов
  и выхода; если данные лежат вне проекта, относительный путь заменяется явной
  настройкой. Приём с кодировкой специфичен для Windows `cmd.exe` — в других
  оболочках кодировка может отличаться.
