# Case: версия определения при архивном воспроизведении и разделение знаменателей

## Узнаваемая ситуация

Определение метрики изменилось, но старый отчёт нужно воспроизвести. Рядом существует похоже названная метрика с другим знаменателем. Триггер: в документации две версии, а слово «одобрение» используется в разных показателях; публикация без версии делает число неоднозначным.

## Исторический пример 1 — пересчёт когорты по двум версиям (C05)

- **Задача и условия:** сравнить `documents/reporting_v1.md` и `reporting_v2.md`; пересчитать старую когорту `created_at` ∈ [2026-10-01, 2026-10-03) на срезе `T = 2026-10-03 00:00:00 UTC`; показать `approval_rate` и отдельно `final_decision_approval_rate`.
- **Что сделали:** по v1 тестовые заявки включались, знаменатель — все зарегистрированные заявки. По v2 `is_test=1` исключается из числителя и знаменателя; знаменатель — все реальные заявки, включая `cancelled` и `manual_review`. `final_decision_approval_rate` посчитали отдельно как `approved / (approved + rejected)` без тестовых.
- **Как проверили:** v1 — `3/8 = 37,50%` (A001, A004, A005); v2 — `2/7 = 28,57%` (A001, A005); `final_decision_approval_rate` — `2/4 = 50,00%` (approved: A001, A005; rejected: A003, A007). A002 `cancelled`, A006 и A008 `manual_review` остаются в знаменателе v2; проверено, что знаменатель `approval_rate` v2 (7) не равен знаменателю финальных решений (4).
- **Что получили:** v1 оформлен как архивный результат, корректный по своему определению; v2 — текущий. В отчёте и сводке закреплены числитель, знаменатель, период когорты, дата среза и версия.

## Исторический пример 2 — переключение версии параметром (C01)

- **Задача и условия:** тот же срез; v1 действовала с 2026-10-01 (тестовые включены), v2 утверждена 2026-10-06 (тестовые исключены из числителя и знаменателя).
- **Что сделали:** посчитали обе версии из одного и того же среза параметром `version`, без второго запроса и без правки SQL.
- **Как проверили:** сравнили числители и знаменатели: v1 — 3 / 8, v2 — 2 / 7; разница — единственная тестовая `approved`-заявка A004 (5 000 ₽); отдельно посчитали `final_decision_approval_rate` = 2 / 4.
- **Что получили:** для архивного среза 2026-10-03 при воспроизведении прежнего отчёта корректна v1 с явной маркировкой версии и даты среза; v2 применяется к текущим публикациям и к явно запрошенному пересчёту того же прошлого. Выбор версии всегда указывается в результате, иначе число неоднозначно.

## Условия переноса

При смене определения вычислять обе версии и маркировать `архив` / `действует`. Версия и дата среза — обязательные атрибуты артефакта, а не комментарий; переключение версии должно быть параметром, чтобы одна и та же сверка не дублировалась. Старый процент не называется ошибочным только из-за смены методики; ошибка — публикация без версии или с перепутанной версией. Для `approval_rate` знаменатель не сокращать до финальных решений. Похожие метрики с общим словом «одобрение» различать по вопросу: доля одобрений среди всех реальных заявок против доли одобрений среди уже принятых решений.
