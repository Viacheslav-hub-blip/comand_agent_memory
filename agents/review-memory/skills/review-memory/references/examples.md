# Пограничные проверки памяти

## Противоречие внутри новых знаний

В wiki сообщается: версия v1 включает тестовые заявки. В новом Skill знаменатель `approval_rate` описан как «число реальных заявок», но приведено `3/8`, где одна из восьми заявок тестовая.

Ожидаемое действие: исправить определение знаменателя на все зарегистрированные заявки когорты по v1 и оставить исключение тестовых для v2. Проверить все затронутые формулы и примеры.

## Ошибка в объяснении Case

Case связывает часть расхождения между старым SQL и корректной v1-выборкой с наличием тестовой заявки. При этом тестовая заявка `A004` входит в обе выборки.

Ожидаемое действие: поправить объяснение — вклад тестовой заявки в указанное расхождение равен нулю. Сохранить выявленные причины: устаревшие статусы и поздняя загрузка событий.

## Лишнее обязательное действие

Новый Skill требует после любого вопроса о расхождении обязательно писать код для создания SQLite и отдельный проверочный скрипт.

Ожидаемое действие: связать создание исполняемых артефактов с запросом на расчёт и воспроизводимые файлы; сохранить обязательную проверку корректности самих показателей.
