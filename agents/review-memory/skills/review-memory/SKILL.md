# Проверка изменений памяти

## Задача

Проверь пригодность предложенной памяти к использованию. Найди ошибки, способные привести рабочего агента к неверному решению, повторным уточнениям или избыточным действиям. Проверь согласованность новой и прежней версии. При разрешении на запись исправляй выявленные ошибки в указанной рабочей копии.

## Вход

- прежняя и предложенная версии памяти;
- перечень затронутых файлов;
- доступные отчёты с извлечёнными сведениями и описанием выполненных проверок;
- разрешённая копия для исправлений.

Начни с изменённых утверждений и непосредственно связанных записей. Доступные материалы анализа используй для проверки спорного смысла; массовое перечитывание исходных диалогов в проверку не входит.

## Проверка

1. **Факты и схема.** Сверь изменённые утверждения с доступными входными сведениями, реальными названиями полей, таблиц, формулами и расчётами. Для технического поля, которого нет в доступной схеме, зафиксируй ошибку; отсутствие схемы отметь как предел проверки. Результат из старого отчёта сам по себе не подтверждает схему новой рабочей области.
2. **Условия действия.** Сравни версии, периоды, проекты, исключения, состав числителя/знаменателя и статусы «реализовано / планируется / предположение». Найди противоречия при совпадающих условиях и сохрани различные версии раздельно.
3. **Действительные и потенциальные причины.** В каждом изменённом Case проверь соответствие объяснения фактически полученным значениям. Отличай проявившийся вклад ошибки от латентного риска. Не приписывай отрицательной проверке положительный эффект.
4. **Сохранность полезного смысла.** Проверь, что не потеряны важные прежние знания, не превращены разовые ограничения в постоянные правила и не приняты неподтверждённые выводы агента за факты.
5. **Границы файлов.** В `AGENTS.md` проверяй общие правила, в `USER_PREFERENCES.md` — устойчивые предпочтения, в личной wiki — проектный контекст, в предметной wiki — факты и определения, в Cases — подтверждённые эпизоды, в Skills — инструкции по самостоятельной задаче. Найди микрокейсы одного механизма, дубли и императивные процессы внутри Wiki.
6. **Нагрузка Skill.** Для нового или существенно изменённого Skill проверь точность основного пути, необходимый набор проверок, условность расширенных исследований и дополнительных файлов, достаточность результата и критерий остановки. Выяви повторяющиеся обязательные шаги, которые не помогают выполнить типовой запрос.
7. **Связи и файлы.** Проверь существование затронутых внутренних ссылок, YAML-заголовки, необходимую локальную доступность артефактов, секреты и лишние персональные данные.

## Исправление

Вноси минимальные исправления, которые прямо следуют из имеющихся материалов: уточни версию, область, численное значение, условие или формулировку действия; восстанови утраченное полезное сведение; убери ошибочный дубль. Проверяй исправление по затронутым связанным утверждениям. Не создавай новый метод или поле, чтобы искусственно согласовать противоречивый результат.

Если для разрешения противоречия не хватает сведений, сохрани установленную часть и опиши открытый вопрос. Не добавляй новые неподтверждённые алгоритмы, формулы или проверки.

Используемые материалы позволяют проверять содержание на данном этапе; итоговая память остаётся самостоятельной. Не дополняй её ссылками на исходные чаты, номера сообщений и журналы доказательств.

## Результат

Верни один JSON-объект:

```json
{
  "decision": "accepted | changes_requested | needs_resolution",
  "summary": "Проверенные изменения, выполненные точечные исправления и оставшиеся риски",
  "findings": [
    {
      "file": "путь",
      "problem": "конкретное оставшееся противоречие или неточность и условия",
      "change": "необходимая правка либо вопрос для разрешения"
    }
  ]
}
```

- `accepted` — существенных оставшихся проблем нет; `findings` пуст.
- `changes_requested` — известные исправления ещё нужно внести.
- `needs_resolution` — существуют несовместимые утверждения, выбор между которыми требует дополнительных сведений.

Если предложенный каталог уже исправлен в пределах разрешённой копии, оцени итоговое состояние. Отрази выполненные исправления в `summary`.

## Завершение

Перечитай изменённые фрагменты, связанные определения и условия применения. Проверь исправления, самостоятельность основного пути новых Skills, отсутствие ложных полей и необоснованно обязательной работы. Ревью завершается оценкой качества памяти; фактическую эффективность нового выполнения задачи по этому Skill не измеряй.

При затруднениях со смысловыми конфликтами используй [пограничные примеры](references/examples.md).
