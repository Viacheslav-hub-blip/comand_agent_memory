# Критерии Skill-кандидата

## Что считать Skill

Skill описывает повторяемый бизнес-процесс целиком. Его цель — провести агента от входного запроса до проверяемого результата через несколько содержательных этапов.

Skill должен содержать:

1. бизнес-цель и условие запуска;
2. входные данные, роли и предпосылки;
3. подготовку и проверку входов;
4. последовательность основных этапов;
5. развилки и критерии выбора;
6. возврат к предыдущему этапу при ошибке;
7. контроль качества;
8. результат и критерий завершения;
9. ограничения процесса.

Обычно из одного диалога извлекается ноль или один Skill.

## Что не считать Skill

Не создавай Skill из:

- одного Case;
- небольшой законченной подзадачи;
- одной ошибки и её исправления;
- одной команды или настройки;
- работы с одним файлом;
- одной проверки tool call;
- одного запроса к базе;
- одного сравнения моделей;
- перечня обычных действий «прочитать, выполнить, проверить»;
- нескольких независимых Cases, объединённых только общей темой.

Полнота маленькой задачи не превращает её в бизнес-процесс.

## Проверка кандидата

Перед добавлением Skill ответь:

1. Какой бизнес-результат получает пользователь?
2. Есть ли несколько этапов, каждый из которых меняет состояние процесса?
3. Есть ли содержательные развилки или возвраты?
4. Определены ли входы, роли и критерии качества?
5. Можно ли выполнить процесс без исходного диалога?
6. Не является ли кандидат одним Case или технической операцией?

Если хотя бы бизнес-результат, этапы и контроль качества не определены, не создавай Skill.

## Формат кандидата

```markdown
### Название бизнес-процесса
- Назначение: ...
- Входы и роли: ...
- Этапы: ...
- Развилки и возвраты: ...
- Контроль качества: ...
- Результат и завершение: ...
- Ограничения: ...
```

Не достраивай отсутствующие этапы общими знаниями. Если история раскрывает только часть процесса, сохрани переносимый механизм как Case.
