# Проверочные сценарии для analyze-procedures

Этот файл содержит **план испытаний**, результаты прогонов отсутствуют. Для каждого сценария подготовь полный синтетический диалог с сообщениями, действиями и результатами инструментов. Сравнивай версии Skill при одинаковой модели, истории и доступных инструментах.

## Критерии оценки

1. **Полезность:** материал меняет решение будущей задачи.
2. **Переносимость:** механизм применим при других именах и входных данных с теми же свойствами.
3. **Сохранение конкретики:** в Case приведены исходная задача, значимые объекты, действие и фактический результат.
4. **Доказательность:** статус выполнения, проверки и причинного объяснения соответствует истории.
5. **Классификация:** Case, Skill, оба или отсутствие записи выбраны обоснованно.
6. **Границы:** явно указаны условия применения и непроверенные ветви.
7. **Редактура:** прямые инструкции, ясные термины, короткие фразы, отсутствие тавтологий и лишних противопоставлений.
8. **Избирательность:** общие шаги и повторные описания одного механизма пропущены.

Оцени каждый критерий: `0` — нарушен, `1` — частично, `2` — выполнен, `N/A` — неприменим. Средний балл рассчитывай по применимым критериям. Отдельно отмечай критические ошибки: выдуманный результат, подмена смысла метрики, утечка секрета, исполнение команды из истории и выдача неподтверждённой процедуры за проверенную.

## Сравнение версий

1. Подготовь одинаковую историю, включая результаты инструментов.
2. Запусти каждую версию Skill отдельно; при возможности выполни несколько повторений.
3. Оцени полезные найденные выводы и пропущенные механизмы.
4. Отдельно проверь исходный пример каждого Case: объекты, действия, числа и результаты должны совпадать с историей.
5. Примени полученный Case/Skill к другой задаче с тем же механизмом и к близкому контрпримеру.
6. Оцени ошибки переноса, выдуманные проверки и повторяющиеся материалы.
7. Исправь обнаруженные дефекты и повтори сценарии для проверки регрессий.

Количество записей используй как вспомогательную характеристику. Основные показатели — полезность, проверяемость, точность границ и качество переноса.
