# Пограничные примеры извлечения

## Устойчивое предпочтение

Диалог: «Для сверок предпочитаю SQL; сначала показывай короткий вывод, затем таблицу».

Результат:

```markdown
## Предпочтения
- Для сверок пользователь предпочитает SQL.
- В отчётах по сверкам пользователь предпочитает сначала короткий вывод, затем таблицу расхождений.
```

## Устранённая неопределённость

Диалог: пользователь уточнил, что «одобрение» — решение по заявке, а «выдача» — движение денег. Документация определяет `requested_amount_rub` как запрошенную сумму.

Результат:

```markdown
## Определения и предметные правила
- **Одобрение** (заявки): решение по заявке, самостоятельный статус и не факт перечисления денег.
- **Выдача** (денежные события): движение средств, учитываемое отдельно от одобрения.
- **requested_amount_rub** (applications): сумма, запрошенная в заявке; не сумма фактической выдачи.
```

## Проектный контекст

Диалог и результаты инструментов установили, что `decision_events` содержит несколько событий для одного `application_id`, а `occurred_at` и `loaded_at` задают разные временные ограничения.

Результат:

```markdown
## Личный и проектный контекст
- **Учебная отчётность «Север»**: `decision_events` хранит историю решений; для воспроизведения состояния на дату T учитываются `occurred_at < T` и `loaded_at < T`.
```

## Разовая задача

Просьба «сохрани этот расчёт сегодня в outputs/C01» сама по себе не становится общим предпочтением. Если каталог является постоянным соглашением продолжающегося проекта, сохрани это соглашение только в его контексте.
