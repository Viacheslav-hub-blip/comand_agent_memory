# Пограничные примеры извлечения

## Устойчивые предпочтения и разовые ограничения

Из истории Бориса: «В SQL предпочитаю именованные CTE и явный список колонок. Обычно использую pandas, но ничего не устанавливай: здесь достаточно csv и sqlite3».

```markdown
## Предпочтения
- Для рабочего SQL пользователь предпочитает именованные CTE и явный список колонок.
- Для обработки данных в Python пользователь обычно предпочитает pandas.
```

Запрет устанавливать пакеты относится к конкретному запуску. Он попадёт в проектный контекст только при подтверждении, что правило сохраняется для следующих задач этого же окружения; глобальной инструкцией пользователя он не становится.

## Устранённая неопределённость

Пользователь объяснил, что «одобрение» — решение по заявке, «выдача» — движение денег. Словарь подтверждает `requested_amount_rub` как запрошенную сумму.

```markdown
## Определения и предметные правила
- **Одобрение** (заявки): решение по заявке, не движение денег.
- **Выдача** (денежные события): движение средств, учитываемое отдельно от одобрения.
- **requested_amount_rub** (`applications`): запрошенная сумма, не фактически перечисленная.
```

## Проектный контекст, пригодный к повторному использованию

Документация устанавливает, что в `decision_events` хранится несколько событий на один `application_id`, а `occurred_at` и `loaded_at` отражают разные временные основания.

```markdown
## Личный и проектный контекст
- **Учебная отчётность «Север»**: `decision_events` содержит историю решений; воспроизведение состояния на дату T учитывает `occurred_at < T` и `loaded_at < T`.
```

## Подтверждение против пересказа агента

В агентском файле перечислено поле `in_scope_v2` для таблицы `applications`, но в доступной схеме его нет. Не добавляй поле в память как установленный факт. При необходимости отметь неопределённость схемы.

## Временные результаты

Путь `outputs/C02/`, результаты `A006` и момент T полезны как состояние продолжающегося конкретного проекта. Не переносить их в общее правило поведения или описание любой истории решений. Воспроизводимое техническое соглашение сохранять отдельно от конкретного результата.
