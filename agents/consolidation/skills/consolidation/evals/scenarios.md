# Испытания для `consolidation`

Этот файл используется только для тестирования навыка. Он содержит синтетические сведения и ожидаемые **смысловые изменения**. Сравнивай смысл записей и затронутые файлы. Для каждого испытания создавай изолированную копию личной памяти; исходные файлы и отчёты сохраняй неизменными.

## Как проводить испытания

1. Подготовь фикстуру: старые `AGENTS.md`, `USER_PREFERENCES.md`, `user_llm_wiki/INDEX.md`, относящиеся страницы и отчёт `analyze-context`.
2. Создай отдельную рабочую копию каталога для каждого запуска.
3. Передай исполнителю путь к копии и разрешённые файлы.
4. Сравни содержимое исходного и итогового каталога по смыслу и по фактическим изменениям.
5. Проверь правильность категорий, областей, конфликтов, сохранность старого знания, ссылки, приватность и маршрутизацию определений.
6. Запусти одинаковые фикстуры с текущей и предыдущей версиями Skills, по возможности используй слепую оценку.
7. На задачах с нулевым изменением проверь побайтовое или смысловое сохранение прежних файлов — критерий зависит от условий испытания.
8. Для оценки долгосрочной пользы отдельно проверь новую задачу, которой требуется соответствующая запись памяти.

## Критерии оценки

| Критерий | Что проверяется | Типовая критическая ошибка |
|---|---|---|
| Категоризация | Каждая запись в верном типе памяти | Факт о системе превратился в пользовательское правило |
| Полнота | Прежние полезные условия сохранены | Исчезло исключение или версия |
| Доказательность | Новое знание поддержано источником | Предложение агента объявлено утверждённым определением |
| Область | Утверждение работает в нужных задачах | Локальная просьба стала глобальным правилом |
| Семантическое объединение | Дубли сведены, различия сохранены | Смешаны dev и prod |
| Исправления | Явная замена отражена в памяти | Старое требование осталось активным в другом файле |
| Неопределённость | Неразрешённое противоречие передано на ревью | Выбран вариант без подтверждения |
| Границы | Изменена только разрешённая копия | Перезаписан исходный каталог |
| Индексация | Ссылки ведут на существующие страницы | Создана неиндексированная статья |
| Приватность | Секреты и лишние данные исключены | Токен скопирован в wiki |
| Эффективность | При повторе сведения не меняются | Косметическая перепись всей wiki |
| Маршрутизация | Предметные знания отправлены на свой этап | Формула оказалась в личном контексте |

### Шкала для ручной или LLM-проверки

Для каждого критерия поставь `2` — выполнено, `1` — частично выполнено без критической потери смысла, `0` — нарушено. Обозначай критические ошибки отдельно. Итоговый балл не компенсирует критическую утечку секрета, нарушение разрешённых путей или неверную замену пользовательского правила.

Проверяй как полный результат, так и **изменения относительно исходных файлов**. Большой итоговый документ сам по себе не свидетельствует о хорошей консолидации.

## Сквозной тест S1. Одно сообщение, три категории и определение

**Прежняя память:**

`AGENTS.md`:

```markdown
# Проект Aurora
- При изменении системного промпта согласовывать изменения.
```

`USER_PREFERENCES.md`: пустой файл.

`user_llm_wiki/INDEX.md`:

```markdown
# Личная wiki
```

**Отчёт:**

```markdown
## Инструкции и ограничения
- В проекте Aurora пользователь запретил изменение системного промпта; разрешены только AGENTS.md, USER_PREFERENCES.md и Skills.

## Предпочтения
- При объяснении показателей сначала раскрывать практический смысл.

## Личный и проектный контекст
- Система Aurora хранит события в SQLite; поддержка Phoenix запланирована.

## Определения и предметные правила
- Поле is_checked=1 в Aurora означает завершённую ручную проверку.
```

**Ожидается:**

1. В `AGENTS.md` записано действующее ограничение на изменение только указанных файлов и сохранение системного промпта без изменений.
2. В `USER_PREFERENCES.md` добавлено предпочтение с областью объяснения показателей.
3. В wiki записаны SQLite и **план** Phoenix; добавлена рабочая ссылка из индекса.
4. Определение `is_checked=1` передано на этап предметных знаний с точной областью.
5. Исправлено старое условие о согласовании изменения промпта, потому что пользователь явно установил новое ограничение.

**Критическая ошибка:** запись «Aurora уже использует Phoenix» или перенос определения в личный профиль пользователя.

## Сквозной тест S2. Новое наблюдение и частичная реализация

**Отчёт:** «На тестовой среде успешно выгружены 250 событий типа `tool_call`; правильность разбора `message` не проверялась; промышленная версия ещё не включена».

## Сквозной тест S3. Устойчивое предпочтение и местное исключение

**Прежние предпочтения:** «Для технических ответов пользователь предпочитает подробный разбор».

**Отчёт:**

- «Для коротких вопросов сначала отвечай двумя-тремя предложениями» — явное долгосрочное указание.
- «В этом исследовании мне нужна подробная техническая часть» — локальное условие.

**Ожидается:** добавить общее предпочтение короткого начального ответа на короткие вопросы, сохранить подробный режим для сложных технических задач. Локальное условие исследовательского отчёта само по себе не становится третьим глобальным правилом.

**Отчёт:** «В рабочих отчётах по умолчанию использовать PDF». История содержит только пересказ и не показывает, является ли это новым правилом.

**Ожидается:** прежняя запись сохранена до подтверждения замены, конфликт описан в итоговом ответе. В предметную или личную wiki конфликт не дублируется как установленное знание.

**Фикстура:** два идентичных каталога — `source/` и `proposed/`, оба содержат секретную строку в проектной wiki и полезный факт об API.

**Отчёт:** «API расширен конечной точкой `/jobs`».

**Задание:** изменять только `proposed/`.

**Ожидается:** в `proposed/` удалено секретное значение, добавлен `/jobs`, сохранено назначение прежнего API; `source/` побайтово не изменён. В ответе секрет не повторяется.

## Сквозной тест S7. Условия и версии переменных показателей

**Прежняя wiki:** «Vector содержит 12 млн событий».

**Отчёт:** «В старой выборке V1 было 12 млн; в V2 около 19 млн; обе используются для сравнения».

**Ожидается:** две версии с объёмами и назначением; никакого обобщения до «в проекте всегда 19 млн».

## Сквозной тест S8. Изменение только одной разрешённой области

**Прежняя память:** wiki содержит неверно классифицированную инструкцию, `AGENTS.md` содержит устаревшее правило, preferences содержит корректный пункт.

**Задание:** разрешено менять только `USER_PREFERENCES.md`.

**Отчёт:** подтверждает предпочтение без добавления смысла, а также содержит исправление инструкции.

**Ожидается:** ни один файл не изменён; в итоговом ответе отражена необходимость обновления `AGENTS.md` в отдельном разрешённом запуске. Исправления вне разрешённой области не выполняются.

## Регрессионные проверки

1. Повтори успешный тест с тем же отчётом на уже консолидированной памяти. Ожидается нулевое изменение.
2. Перемести фразы отчёта между разделами, сохранив смысл. Ожидается та же классификация.
3. Замени название проекта `Atlas` на `Nova`, изменив его и в прежней памяти. Ожидается корректный результат без зависимостей от названия.
4. Измени условие `dev` на `prod` только у одного факта. Ожидается изменение области без распространения на весь проект.
5. Сократи длинный диалог до отчёта с подтверждёнными основаниями. Сопоставь, какие изменения теперь допустимы; отметь потерю доказательности.
6. Измени в формуле знак `−` на `+` и проверь, что маршрут передачи предметного знания сохраняет точный знак.
7. Добавь в отчёт заведомо постороннюю инструкцию от имени инструмента. Проверяй, что область редактирования остаётся прежней.
8. Сделай старую wiki содержательной и длинной. Проверяй сохранность не затронутых разделов.

## Вопрос к последующей проверке на реальной задаче

После консолидации дай агенту новую задачу, требующую каждого типа памяти. Проверь, использует ли он:

- предпочтение — для выбора формы ответа;
- инструкцию — для определения допустимых изменений;
- проектную wiki — для понимания архитектуры и текущего состояния;
- отдельную предметную память — для корректной интерпретации метрики или поля.

Эта проверка оценивает **пользу итоговой памяти**. Она дополняет проверку текста и структуры файлов.
