# Консолидация личной памяти

## Задача

Объедини новые сведения с существующей памятью пользователя. Сохрани полезный смысл, исправления и условия применения. Обнови только указанные файлы рабочей копии.

## Области памяти

- **`AGENTS.md`** — общие инструкции и полномочия, применимые к разным проектам. Формулируй как прямые действия агента с необходимыми условиями.
- **`USER_PREFERENCES.md`** — устойчивые предпочтения общения, инструментов и формата результата, применимые за пределами отдельного проекта.
- **`user_llm_wiki/`** — личный и проектный контекст: цели, архитектура, состав систем, рабочие соглашения, данные, ограничения, состояние и планы.

Предметные определения, прошлые эпизоды решения и воспроизводимые процедуры находятся вне области редактирования этого Skill. Проектно-ограниченные правила и предпочтения сохраняй в соответствующей статье личной wiki только при их пользе для продолжения проекта.

## Вход

- новые сведения о пользователе и его проектах;
- действующие файлы личной памяти;
- путь к разрешённой рабочей копии и границы изменения.

Начни с новых сведений и соответствующих текущих разделов. Для затронутой статьи используй `INDEX.md`. Сохраняй неизменённые файлы без повторного переписывания.

## Порядок действий

1. **Раздели сведения по смыслу.** Выдели самостоятельные утверждения, область действия, версии и статус: действует, реализовано, планируется, предположительно. Определи, какие сведения пригодятся при продолжении работы.
2. **Выбери место хранения.** Для `AGENTS.md` и `USER_PREFERENCES.md` потребуй подтверждённой применимости за пределами одной задачи и проекта. Проектно-ограниченные факты и устойчивые локальные соглашения размещай в wiki. Разовые указания сохраняй лишь при необходимости продолжить ещё не законченную работу.
3. **Сопоставь с памятью.** Различай повтор, дополнение, исправление, отдельную версию, устаревание и конфликт. Проверяй, что новый факт не выведен только из недостоверного резюме агента.
4. **Сделай минимальную правку.** Обнови имеющийся раздел либо создай статью самостоятельной темы. Объедини смысловые повторы, сохрани прежние подтверждённые сведения и реальные исключения. При конфликте оставь установленную часть и опиши вопрос в результате.
5. **Проверь применимость.** Отличай постоянное правило размещения результатов от исторического пути к отдельному артефакту. Для прошлого рабочего файла указывай исторический статус; его наличие в новом окружении проверяется при выполнении новой задачи.
6. **Проверь итог.** Проверь категорию, точные имена сущностей, статусы, внутренние ссылки и отсутствие повторения предметного процесса в виде дополнительных обязательных инструкций.

## Правила содержания

- Формулируй запись как готовую информацию для будущей работы. Исключай пересказ диалога, номера сообщений, ссылки на трассы, перечни исходных свидетельств и предложения перечитать историю.
- Указывай точные названия проектов, технологий, полей, файлов и версий, когда они нужны для работы.
- Для проектных сведений различай реализованное, обсуждаемое и запланированное. Для изменчивого статуса сохраняй существенный временной контекст.
- Общие инструкции делай короткими и применимыми к разным задачам. В личной wiki описывай проектные факты, ресурсы, состояние и соглашения; подробные алгоритмы повторного выполнения не превращай в предписания из проектной статьи.
- Сохраняй предпочтения в установленной области. Временный запрет на установку пакетов, единичный формат отчёта и цель отдельного запуска не расширяй на будущие независимые задачи.
- Сохраняй точные исторические пути только для ориентирования в продолжающемся проекте; не обещай доступность старых файлов в текущей рабочей области.
- Исключай секреты, учётные данные и лишние личные сведения.
- Внутренние ссылки wiki используй для навигации по самой памяти; ссылки на рабочие ресурсы сохраняй только тогда, когда они необходимы для выполнения задач пользователя.

## Результат

Обнови разрешённую рабочую копию. Верни краткий итог обычным текстом:

- какие файлы изменены и какой полезный смысл добавлен или уточнён;
- какие существенные противоречия остались открытыми;
- если изменений нет — почему текущая память уже достаточна.

## Завершение

Перечитай изменённые фрагменты, проверь внутренние ссылки, различие общих и локальных правил и границы полномочий. Работа завершена, когда в памяти сохранён пригодный для продолжения контекст без случайных предписаний отдельного запуска и без требования перечитывать первоначальный разговор.

При спорном распределении сведений используй [примеры размещения](references/examples.md).
