# Правила составления Agent Skills

## Формат

По [спецификации Agent Skills](https://agentskills.io/specification):

- Skill — каталог с файлом `SKILL.md`. В начале файла — YAML, затем инструкции в Markdown.
- Обязательные поля YAML: `name` и `description`.
- `name`: от 1 до 64 символов, строчные буквы, цифры и дефисы. Совпадает с именем
  каталога; без дефиса в начале и конце и без двойных дефисов.
- `description`: от 1 до 1024 символов; описывает действие skill и ситуации,
  в которых его нужно применять.
- Структура текста инструкций не фиксирована. Рекомендуются шаги, примеры входов
  и результатов, а также особенности задачи.
- `scripts/`, `references/` и `assets/` необязательны: код, справочные материалы
  и шаблоны добавляются по необходимости.
- Ссылки на файлы задаются относительно каталога skill. Детали выносятся в
  reference, на который ссылается `SKILL.md`.

## Критерий содержания

В этом проекте Skill хранит полный повторяемый бизнес-процесс. Спецификация
Agent Skills задаёт формат каталога, но сама по себе не означает, что любая
законченная техническая задача должна стать Skill.

Публикуй Skill только при наличии:

- бизнес-цели и условия запуска;
- входных данных, ролей и предпосылок;
- подготовки и проверки входов;
- нескольких содержательных этапов;
- развилок и возвратов при ошибке;
- контроля качества;
- конечного результата и критерия завершения.

Одна настройка, ошибка, проверка, команда, файл, запрос, tool call или модельный
бенчмарк остаются Case. Не соединяй независимые Cases в искусственный Skill.
Обычно материалы одного диалога дают ноль или один Skill.

## Содержание инструкций

По [рекомендациям для авторов skills](https://agentskills.io/skill-creation/best-practices):

- Описывай один связный бизнес-процесс. Не дроби его этапы на отдельные Skills.
- Используй опыт выполнения задач, особенности данных, инструментов и соглашений.
  Общих советов вроде «следуй лучшим практикам» недостаточно.
- Сохраняй шаги, которые помогли решить задачу, поправки к подходу и форматы
  входных и выходных данных.
- Добавляй сведения, которых агенту не хватает для задачи. Не объясняй то,
  что он уже умеет делать без инструкции.
- Формулируй действия: что сделать и как проверить результат.
- Для операций, где важен точный порядок, задавай его явно. Если выбор зависит
  от ситуации, опиши условия выбора.
- Предлагай способ по умолчанию; альтернативы добавляй, когда они нужны для выбора.
- Используй примеры и шаблоны, когда они уточняют требуемый результат.
- Держи `SKILL.md` кратким. Рекомендованный предел — 500 строк и 5000 токенов.
  Детали выноси в `references/` и указывай, когда их читать.
- Проверяй skill на задачах и изучай ход выполнения, а не только итоговый ответ.
  По результатам уточняй инструкции и удаляй лишнее.
