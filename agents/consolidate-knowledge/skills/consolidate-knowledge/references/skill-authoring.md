# Требования к опубликованному Skill

Skill применяется к самостоятельному классу запросов. Создавай его, когда известны входные данные, воспроизводимый способ действия, проверка и достаточный результат. Кандидат может описывать исследование, аналитику, программирование, диагностику или бизнес-процесс.

## Состав

```text
skill-name/
  SKILL.md
  references/   # только когда подробности нужны для отдельных случаев
  scripts/      # только проверенные повторяемые операции
  assets/       # только нужные шаблоны результата
```

Начало `SKILL.md`:

```yaml
---
name: skill-name
description: "Когда и для какой задачи применять Skill."
---
```

В основном тексте изложи назначение, вход, действия, условия ветвления, необходимые проверки и критерий завершения. Сформулируй прямые инструкции, сохрани точные операции и значения, необходимые для их выполнения.

## Самостоятельность

Skill должен быть исполним по своему содержанию. Названия других Skills, этапы извлечения памяти и особенности загрузки файлов конкретного harness ему не нужны. Если без локального определения или данных работу выполнить нельзя, укажи, какие входы следует получить или проверить.

## Экономность

- Опиши основной путь коротко.
- Активируй дополнительные действия по наблюдаемому условию.
- Используй уже выполненную проверку, если она достаточна и входные данные не изменились.
- Создавай только нужные для ответа артефакты.
- Условие завершения связывай с запросом пользователя.

## Качество

Проверь согласованность определения, формулы и версии во всём опубликованном Skill. Не приписывай прошлому опыту непроведённые проверки. Длинные примеры размещай в Case; точную предметную терминологию — в wiki. При этом Skill должен содержать достаточно информации для выполнения своей собственной процедуры.
