# Критерии создания и оформления опубликованного Skill

Создавай новый Skill, когда имеется самостоятельная повторяемая задача с отличающимися целью, входами, способом или результатом. Если сведения уточняют уже существующий процесс, обнови его. Проверку без самостоятельной цели включай в соответствующую процедуру. Варианты и эпизоды одного переносимого механизма объединяй, сохраняя конкретные проверенные результаты в Cases.

## Структура

```text
skill-name/
  SKILL.md
  references/    # только подробности по отдельным ветвям
  scripts/       # реально доступные и проверенные исполняемые операции
  assets/        # только необходимые шаблоны результата
```

YAML-заголовок:

```yaml
---
name: skill-name
description: "Конкретная самостоятельная задача и условия выбора."
---
```

В `SKILL.md` сформулируй цель, необходимые входы, основной алгоритм, условия выбора ветвей, необходимые проверки, критерий достаточного результата и завершения. Используй прямые повелительные формулировки.

## Граница обязательности

- В основной путь помещай действия, необходимые для решения типовой задачи.
- Для проверки помечай, какую ошибку она должна исключить; сохраняй необходимую для корректности проверку.
- Для дополнительных действий формулируй наблюдаемое условие: расхождение, недостаток данных, изменение схемы, высокий риск или прямое требование пользователя.
- Независимые реализации, расширенные исследования, мутационные тесты и создание вспомогательных файлов выполняй при их необходимости.
- Останавливай процесс после проверенного результата и подготовки запрошенных артефактов.
- При пригодных существующих файлах или готовой реализации проверяй соответствие новым входам и переиспользуй их.

## Самостоятельность и размер

Основной алгоритм должен быть исполним по одному `SKILL.md` с поданными входами. В дополнительные файлы помещай крупные примеры, специальную справку и необязательные ветви. Следи за объёмом основного текста относительно ограничения чтения рабочего инструмента; фиксированное максимальное число строк не требуется. В самом Skill описывай его собственную задачу, без упоминаний других Skills или шагов создания памяти.

## Проверка результата

Сверь версию, формулу, точные поля и условия с доступной документацией. Отделяй реально сработавшую причину от латентной. Проверь, что основной путь не принуждает создавать дополнительные SQL, Python-скрипты или отчёты при запросе, который этого не требует. Сохраняй подтверждённый механизм без реконструкции несуществовавших исторических проверок.
