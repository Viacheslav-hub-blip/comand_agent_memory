# Консолидация знаний

## Задача

Объедини новые предметные сведения и опыт решения задач с существующим каталогом. Результат должен помогать агенту правильно понимать термины, узнавать похожие ситуации и выполнять подтверждённые процедуры на новых входных данных.

## Области каталога

| Файл | Содержание |
|---|---|
| `wiki/` | Определения, формулы, схемы, версии, факты и условия действия предметных правил |
| `cases/` | Обобщённая ситуация и конкретный прошлый эпизод: задача, действия, проверка, результат, условия переноса |
| `skills/<name>/SKILL.md` | Самостоятельный воспроизводимый способ решения класса задач: вход, действия, развилки, проверки и результат |
| `INDEX.md` | Краткие описания материалов и внутренние ссылки на них |

Каталог сохраняет знания, а порядок подключения файлов к рабочему агенту определяется его окружением. Не закладывай в содержимое обязательный порядок чтения файлов.

## Вход

Полученные определения, Cases и кандидаты процедур, текущий каталог и разрешённая рабочая копия. Читай `INDEX.md` и относящиеся к новым сведениям записи. Редактируй только разрешённую копию.

## Порядок работы

1. **Найди совпадающие механизмы.** Сопоставь новые сведения с существующими по задаче, входам, способу, результату, версии и области применения. Предпочти дополнение существующей записи созданию новой с тем же назначением.
2. **Проверь самостоятельность новой записи.** Создавай отдельный Case при новом переносимом выводе или существенно иных условиях применения. Объединяй несколько эпизодов одного механизма, сохраняя конкретные результаты каждого. Создавай отдельный Skill, когда он решает самостоятельный класс задач с отличающимися целью, входами, процедурой или результатом; отдельную проверку встрои в действующий процесс, если самостоятельной задачи нет.
3. **Раздели содержание.** Точные термины, схемы, версии и факты помести в wiki. Проверенный эпизод и результат — в Case. Действия и критерии завершения — в Skill. Излагай факты проекта описательно; инструкции по выполнению процедуры размещай в Skill.
4. **Согласуй версии и причины.** Сохраняй разные условия и периоды раздельно. Различай фактически сработавший дефект и латентный риск. Для несовместимых утверждений с одинаковыми условиями сохраняй установленную часть и указывай открытый конфликт.
5. **Сформируй готовые материалы.** Сохраняй техническую точность и переносимый основной путь. Привязывай расширенную диагностику, вторую реализацию, мутационные тесты и дополнительные артефакты к условиям, в которых они нужны. Используй существующие проверенные заготовки, если их можно адаптировать к новым данным.
6. **Обнови навигацию.** Добавь или исправь короткие записи в `INDEX.md`, проверь пути к реально доступным внутренним файлам.
7. **Проверь результат.** Сопоставь определения между связанными Wiki, Cases и Skills, проверь точные поля относительно доступной схемы, версии, расчёты, фактические проверки и условность дополнительных действий. Убедись, что основной путь нового Skill выполним по его тексту.

## Правила для Wiki

Фиксируй однозначное определение вместе с областью, версией и важными исключениями. Разные версии показателя описывай отдельно. Проверяй существенные имена таблиц и полей по доступной схеме, отмечай непроверенную часть без выдумывания колонок. Описывай факты и соглашения как знания о предметной области. Алгоритмы, обязательные шаги и требования создавать отчёты записывай в предназначенные для исполнения процедуры. Излагай установленный смысл самостоятельно, без указаний перечитать исходный чат.

## Правила для Cases

Case содержит:

1. **Обобщённую ситуацию:** по каким признакам этот опыт применим.
2. **Конкретный эпизод:** исходная задача, значимые таблицы и поля, реально выполненный приём, фактическая проверка, результат и статус.
3. **Условия переноса:** что сопоставить в новой задаче.

Сохраняй реальные числа, имена важных сущностей и причины ошибок, когда они нужны для понимания приёма. Отмечай сработавшие причины и не проявившиеся риски раздельно, с фактическим вкладом в исходном случае. Отдельно указывай рекомендованную будущую проверку, если она отличается от реально проведённой. Объединяя разные эпизоды одного механизма, сохраняй конкретную задачу, действие и проверенный результат каждого.

## Правила для Skills

Создавай Skill, когда можно описать самостоятельное выполнение аналогичной задачи по новым входам. Используй краткую структуру:

- YAML `name`, `description` — назначение и условие применения;
- цель и вход;
- последовательность необходимых действий;
- условные развилки и точечные проверки;
- достаточный результат и критерий завершения.

Включай основной проверенный путь, который достаточен для решения задачи при типовых входах. Отделяй необходимые проверки правильности от условных проверок, дополнительных исследований и расширенного тестирования. Для каждого расширения укажи наблюдаемое условие: недостаток данных, найденное расхождение, технический риск или явное требование пользователя. Добавь критерий остановки после правильного результата и запрошенных артефактов. Сохраняй самостоятельность: Skill содержит достаточные инструкции для своей задачи и не требует предварительного выполнения других Skills или этапов создания памяти.

Указывай точные технологии и команды, когда от них зависит выполнение. Для переносимых процедур отделяй постоянный метод от меняющихся параметров и истории отладки конкретной оболочки. Основной `SKILL.md` делай удобным для целостного чтения штатным инструментом; большие примеры и необязательные подробности выноси в `references/` и `assets/`, сохраняя исполнимость основного пути без их обязательного чтения. Готовые шаблоны кода или SQL добавляй в `scripts/` или `assets/`, когда они действительно доступны и проверены; проверяй рабочие ссылки. Не создавай файлы для демонстрации полноты процесса.

## Самопроверка публикации

- Определения и версии согласованы во всех затронутых материалах.
- В Case сохранён конкретный проверенный опыт и его границы.
- Каждый новый Case и Skill добавляет самостоятельный переносимый смысл; близкие эпизоды объединены без потери конкретики.
- Wiki содержит точные сведения, а действия и обязательные процессы изложены в Skills.
- Каждый Skill задаёт одну выполнимую задачу и содержит достаточный основной путь и критерий завершения.
- Расширенные проверки и артефакты имеют наблюдаемое условие включения; ранее достигнутый достаточный результат не требует повторной работы.
- Ссылки каталога указывают на существующие файлы.
- Текст готов для использования без доступа к исходной истории.
- Нет ссылок на диалоги, идентификаторов реплик, трасс и библиографии доказательств; сохранены лишь рабочие файлы и ресурсы, необходимые для выполнения описанных задач.
- Отредактированы только разрешённые файлы, исключены секреты и лишние персональные сведения.

## Результат

Обнови `wiki/`, `cases/`, `skills/` и `INDEX.md` в необходимой части. Верни краткий список смысловых изменений и вопросов, требующих разрешения. При отсутствии новых знаний сохрани текущий каталог.

При создании нового Skill используй [критерии оформления](references/skill-authoring.md) для проверки структуры.
