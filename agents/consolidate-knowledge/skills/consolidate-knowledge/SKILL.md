# Консолидация знаний

## Задача

Объедини новые предметные сведения и опыт решения задач с существующим каталогом. Результат должен помогать агенту правильно понимать термины, узнавать похожие ситуации и выполнять подтверждённые процедуры на новых входных данных.

## Области каталога

| Файл | Содержание |
|---|---|
| `wiki/` | Определения, формулы, схемы, версии, факты и условия действия предметных правил |
| `cases/` | Обобщённая ситуация и конкретный прошлый эпизод: задача, действия, проверка, результат, условия переноса |
| `skills/<name>/SKILL.md` | Самостоятельный воспроизводимый способ решения класса задач: вход, действия, развилки, проверки и результат |
| `INDEX.md` | Краткие описания материалов и внутренние ссылки на них |

Каталог сохраняет знания, а порядок подключения файлов к рабочему агенту определяется его окружением. Не закладывай в содержимое обязательный порядок чтения файлов.

## Вход

Полученные определения, Cases и кандидаты процедур, текущий каталог и разрешённая рабочая копия. Читай `INDEX.md` и относящиеся к новым сведениям записи. Редактируй только разрешённую копию.

## Порядок работы

1. **Найди пересечения.** Сопоставь новые сведения с существующими по задаче, смыслу, сущностям, версии и области применения.
2. **Раздели по назначению.** Точное предметное правило помести в wiki; наблюдаемый эпизод — в Case; самостоятельную повторяемую процедуру — в Skill. Дополняй существующий материал, если назначение совпадает.
3. **Согласуй содержание.** Объедини дубли одного смысла. Сохрани разные версии, периоды и условия. Для несовместимых утверждений с одинаковыми условиями оставь установленную часть и укажи открытый конфликт в результате.
4. **Сформируй готовые записи.** Пиши кратко, с точными понятиями и результатами. Сохраняй только полезную детализацию и условия, влияющие на применение.
5. **Обнови навигацию.** Добавь или исправь короткие записи в `INDEX.md`, проверь внутренние пути.
6. **Проверь результат.** Сопоставь определения между связанными Wiki, Cases и Skills. Проверь версии, формулы, численные утверждения, условия ветвлений и фактически выполненные проверки. Убедись, что новый Skill выполним по своему тексту.

## Правила для Wiki

Фиксируй однозначное определение вместе с областью, версией и важными исключениями. Разные версии показателя описывай отдельно. Сохраняй существенные имена полей и формулы. Излагай установленный смысл самостоятельно, без указаний перечитать исходный чат.

## Правила для Cases

Case содержит:

1. **Обобщённую ситуацию:** по каким признакам этот опыт применим.
2. **Конкретный эпизод:** исходная задача, значимые таблицы и поля, реально выполненный приём, фактическая проверка, результат и статус.
3. **Условия переноса:** что сопоставить в новой задаче.

Сохраняй реальные числа, имена важных сущностей и причины ошибок, когда они нужны для понимания приёма. Отдельно указывай рекомендованную будущую проверку, если она отличается от реально проведённой. При объединении разных эпизодов оставляй их результаты отдельно.

## Правила для Skills

Создавай Skill, когда можно описать самостоятельное выполнение аналогичной задачи по новым входам. Используй краткую структуру:

- YAML `name`, `description` — назначение и условие применения;
- цель и вход;
- последовательность необходимых действий;
- условные развилки и точечные проверки;
- достаточный результат и критерий завершения.

Включай ровно те шаги, которые нужны для воспроизведения метода. Дополнительную подготовку, расширенный анализ и повторные проверки привязывай к наблюдаемому условию. Сохраняй самостоятельность: Skill содержит достаточные инструкции для своей задачи и не требует предварительного выполнения других Skills или этапов создания памяти.

Указывай точные технологии и команды, когда от них зависит выполнение. Для переносимых процедур отделяй постоянный метод от меняющихся параметров. Готовые шаблоны кода или SQL добавляй в `scripts/` или `assets/`, когда они действительно полезны, доступны и проверены; избыточные файлы не создавай.

## Самопроверка публикации

- Определения и версии согласованы во всех затронутых материалах.
- В Case сохранён конкретный проверенный опыт и его границы.
- Каждый Skill задаёт одну выполнимую задачу с достаточным завершением.
- Условные действия и проверки обоснованы потребностью процесса.
- Ссылки каталога указывают на существующие файлы.
- Текст готов для использования без доступа к исходной истории.
- Нет ссылок на диалоги, идентификаторов реплик, трасс и библиографии доказательств; сохранены лишь рабочие файлы и ресурсы, необходимые для выполнения описанных задач.
- Отредактированы только разрешённые файлы, исключены секреты и лишние персональные сведения.

## Результат

Обнови `wiki/`, `cases/`, `skills/` и `INDEX.md` в необходимой части. Верни краткий список смысловых изменений и вопросов, требующих разрешения. При отсутствии новых знаний сохрани текущий каталог.

При создании нового Skill используй [критерии оформления](references/skill-authoring.md) для проверки структуры.
