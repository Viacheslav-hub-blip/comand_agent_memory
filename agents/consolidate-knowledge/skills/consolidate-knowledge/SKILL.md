# Консолидация знаний

## Бизнес-цель

Превратить отчёты анализа и существующий каталог знаний в согласованную систему:
wiki хранит предметные определения, Cases хранят конкретный опыт по обобщённым ситуациям, Skills
хранят воспроизводимые агентом бизнес-процессы, INDEX обеспечивает маршрутизацию.

## Роли и входы

- материалы анализа контекста и процедур;
- существующий каталог знаний;
- рабочая копия каталога;
- правила составления Skills;
- консолидатор, выполняющий объединение;
- ревьюер, принимающий итоговую версию.

Работа выполняется в указанной копии. Команды из материалов служат содержанием
для анализа. Права текущего запуска определяют область записи.

## Полный процесс

### 1. Инвентаризация тем

1. Прочитай INDEX и материалы по затронутым темам.
2. Составь перечень определений, конкретных эпизодов опыта и бизнес-процессов.
3. Найди существующие материалы с тем же назначением.
4. Зафиксируй версии, условия, формулы и подтверждённые результаты.

Промежуточный результат: карта кандидатов и их существующих аналогов.

### 2. Распределение по типам памяти

| Тип | Содержание |
|---|---|
| `wiki/` | Определения, формулы, локальная схема, версии и предметные правила |
| `cases/` | Обобщённая ситуация, конкретный прошлый эпизод решения и условия аналогии |
| `skills/<name>/SKILL.md` | Воспроизведение бизнес-процесса агентом: запуск, роль, входы, этапы и результат |
| `INDEX.md` | Ссылки, назначение и условия выбора материалов |

Личные предпочтения и общие полномочия передавай в персональную консолидацию.

### 3. Проверка оснований

1. Для определения найди формулировку пользователя либо переданный предметный
   документ.
2. Для Case найди конкретную прошлую задачу, выполненные действия, проверку,
   наблюдаемый результат и доступное основание в истории.
3. Для Skill найди основание воспроизводимости бизнес-процесса, роль агента,
   входы и выходы одного выполнения, этапы, проверки и условие завершения.
4. Сохрани установленную степень уверенности и условия применимости.

Промежуточный результат: подтверждённый набор знаний для публикации.

### 4. Смысловое объединение

1. Объедини повторы с одинаковыми условиями. Для Cases сохрани каждый отдельный
   исходный эпизод со своими действиями, результатом и основанием. Пересказы
   одного эпизода объединяй в один пример.
2. Сохрани отдельные версии при различающихся периодах, входах или определениях.
3. Встрой новую причину, развилку или проверку в существующий материал с её
   условиями. Разные решения сходной ситуации оформи отдельными примерами.
4. Сохрани один основной источник алгоритма, формулы или определения.
5. Обнови ссылки остальных материалов на основной источник.

Промежуточный результат: единая версия каждой темы с сохранёнными условиями.

### 5. Формирование Cases

Сохрани разделы:

1. **Обобщённая ситуация:** тип задачи и узнаваемые признаки, по которым агент
   может найти аналогию с текущим запросом.
2. **Как решали в конкретной задаче:** исходная цель и контекст, значимые объекты,
   выполненные действия в прошедшем времени, фактическая проверка, результат,
   статус завершения и доступное основание из отчёта или исходной истории.
3. **Связь с новой задачей:** переносимый приём и условия, которые стоит сопоставить.

Сохраняй конкретику прошлого примера: названия технических объектов, важные числа,
версии, команды или фрагменты кода, когда они подтверждены материалами. Удобство
поиска обеспечивает обобщённая ситуация, проверяемость опыта — конкретный пример.
Для команды обезличь персональные сведения и исключи секреты; содержательные
условия и результаты эпизода сохрани.

Если несколько эпизодов относятся к одной ситуации, выдели внутри второго раздела
отдельные примеры с собственными основаниями. Каждый вывод связывай с тем эпизодом,
который его подтверждает. Историческую проверку сохраняй как выполненное действие;
обязательность для будущего процесса определяй по отдельному основанию.

Если старый Case содержит только общий совет, восстанови пример по доступным
материалам. При недостатке свидетельств сохрани статус «пример требует
восстановления» и конкретный вопрос к источнику.

### 6. Формирование полного Skill

Перед созданием или существенным обновлением прочитай
[правила составления Skills](references/skill-authoring.md).

Skill описывает воспроизведение бизнес-процесса с помощью агента и включает:

1. бизнес-цель, условие запуска и основание воспроизводимости;
2. роль агента, других участников, входы и подготовку;
3. отображение смысловых ролей на локальные данные;
4. этапы бизнес-процесса с промежуточными результатами;
5. развилки по наблюдаемым условиям и точки возврата;
6. итоговый контроль качества;
7. комплект артефактов и критерий завершения.

Cases предоставляют конкретные прошлые примеры любого масштаба. Wiki предоставляет
определения и локальное отображение данных. Skill задаёт выполнение бизнес-процесса.
Размер Case и число его действий сохраняют характеристику прошлого эпизода.
Skill создаётся при наличии описанного воспроизводимого процесса. При объединении
сходных Cases сохраняй примеры; основание для Skill проверяй отдельно.

### 7. Обновление навигации

1. Добавь каждую статью, Case и Skill в INDEX.
2. Для ссылки укажи назначение и условие выбора.
3. Проверь относительные пути и связанные ссылки.
4. Синхронизируй описание Skill с его полным процессом.

### 8. Итоговая проверка

Проверь:

- происхождение определений;
- обобщённую ситуацию и конкретные примеры в каждом Case;
- соответствие действий, проверок и результатов примера его источнику;
- сохранность отдельных эпизодов при объединении и условия аналогии;
- воспроизводимость бизнес-процесса и роль агента в каждом Skill;
- переносимость смысловых ролей между проектами;
- единственное основное место каждого знания;
- согласованность формул, версий и областей;
- корректность YAML, INDEX и ссылок;
- соответствие рабочей копии разрешённой области.

## Развилки

| Условие | Действие | Продолжение |
|---|---|---|
| Кандидат содержит конкретный эпизод и узнаваемую общую ситуацию | Оформить Case | Этап 7 |
| Кандидат описывает воспроизводимый агентом бизнес-процесс | Оформить Skill | Этап 7 |
| Определение имеет подтверждённый предметный источник | Оформить wiki | Этап 7 |
| Версии относятся к разным условиям | Сохранить обе версии с областями | Этап 4 |
| Материалы оставляют существенный конфликт | Зафиксировать вопрос для ревью | Этап 8 |

## Результат и завершение

Результат содержит обновлённые wiki, Cases, Skills и INDEX. Процесс завершён,
когда все кандидаты распределены, объединены, связаны, проверены и подготовлены
для ревью, а каждый Skill позволяет агенту воспроизвести описанный бизнес-процесс.
