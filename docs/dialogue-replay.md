# Диалоговая проверка памяти

В проверке участвуют два отдельных экземпляра модели. Решающий агент выполняет
задачу. Пользователь-тестировщик знает конечную цель, все исходные пользовательские
реплики и эталон; после каждого ответа выбирает дальнейший ход диалога.

Первое сообщение решающему агенту дословно совпадает с первой репликой исходного
чата. Следующие реплики поступают по одной. Тестировщик может пропустить уже
учтённое уточнение, перейти к расчёту или оформлению, подтвердить достижение цели
либо завершить проверку с открытыми вопросами.

Память подключается при инициализации DeepAgents через параметры `memory` и
`skills`. В `memory` поступают существующие AGENTS.md, USER_PREFERENCES.md и
индексы справочников. В `skills` передаются каталоги навыков: DeepAgents показывает
их описания, а решающий агент выбирает применимые процессы. Полное содержимое
каждого навыка загружается по обращению агента к соответствующему файлу.

Решающий агент использует базовый системный промпт DeepAgents. Параметр
`system_prompt` при его создании опущен. Пользователь-тестировщик получает
отдельную инструкцию своей роли с целью, сценарием и эталоном.

## Что получает каждая сторона

| Материал | Решающий агент | Пользователь-тестировщик |
| --- | --- | --- |
| Первая исходная реплика | Сразу, дословно | При инициализации |
| Последующие реплики | По выбору тестировщика, по одной | При инициализации |
| Личная и командная память | Через параметры инициализации выбранного варианта | Для выбора следующей реплики хватает ответов и результатов |
| Эталон и описание конечной цели | Закрытая часть проверки | При инициализации |
| Созданные файлы | В своей рабочей области | Текст, размеры и хеши после каждого хода |
| Решения тестировщика | Внутренняя часть проверки | В своём контексте и журнале |

Тестировщик возвращает номер исходной реплики. Управляющий код сам берёт её
дословный текст из сценария. Это сохраняет происхождение каждого пользовательского
сообщения. Номер следующей реплики должен увеличиваться: например, переход 1 → 3
пропускает вторую реплику, если агент уже учёл её смысл.

Разрешения на дальнейшее действие входят в исходные реплики. Тестировщик учитывает
их при выборе: просьба выполнить расчёт и просьба сохранить результат могут
потребовать следующих ходов даже при правильном предварительном объяснении.

## Файлы реализации

| Файл | Назначение |
| --- | --- |
| `run_dialogue_replay.py` | Создание чистых областей и сравнение вариантов |
| `command_agent_memory/evaluation/scenario.py` | Чтение отдельных исходных реплик |
| `command_agent_memory/evaluation/dialogue.py` | Две роли, переходы между репликами и журналы |
| `agent_runtime.py` | Общая сборка агента, подключение памяти и сохранение контекста |
| `replay_evaluation.py` | Подключение диалоговой проверки к публикации памяти |
| `docs/examples/replay-anna/dialogue-scenario.json` | Исходный диалог и цель Анны |
| `tests/test_dialogue_replay.py` | Локальные проверки границ данных и управления диалогом |

Исходные пользовательские реплики Анны читаются из четырёх блоков `text` в
`docs/examples/synthetic-team/chats/01-anna-reconciliation.md`. Заголовки и
пояснения оператора относятся к подготовке сценария.

Сценарий также поддерживает явный список `messages`. Поле `request` при наличии
должно точно совпадать с первым элементом списка. Сценарии с одним `request`
сохраняют прежний способ выполнения; для диалогового режима нужны отдельные
реплики. Старые одношаговые измерения сохраняют собственную методику.

## Подготовительная проверка

Команда показывает первую реплику и проверяет расположение материалов локально:

```powershell
$python = 'C:/Users/Slav4ik/PycharmProjects/deepagent/.venv/Scripts/python.exe'
& $python -X utf8 run_dialogue_replay.py `
  --scenario docs/examples/replay-anna/dialogue-scenario.json `
  --model deepseek/deepseek-v4.1-flash-1017 `
  --variant both `
  --memory-source data/fc/20261025T182357Z-new-skills/w/101 `
  --validate-only
```

## Сравнение с последней личной памятью Анны

Для выполнения обеих проверок уберите `--validate-only` из команды выше.
Первый вариант получает исходные файлы задачи и пустую память. Второй получает
те же файлы и выбранный снимок памяти. Каждый вариант создаёт отдельного решающего
агента и отдельного пользователя-тестировщика. Внутри одного диалога контекст
решающего агента продолжается между ходами.

Командные знания можно подключить дополнительно:

```powershell
& $python -X utf8 run_dialogue_replay.py `
  --scenario docs/examples/replay-anna/dialogue-scenario.json `
  --model deepseek/deepseek-v4.1-flash-1017 `
  --variant both `
  --memory-source data/fc/20261025T182357Z-new-skills/w/101 `
  --team-knowledge data/fc/20261025T182357Z-new-skills/team-knowledge
```

Параметр `--tester-model` выбирает другую модель тестировщика. По умолчанию обе
роли используют модель из `--model`. Варианты `--variant no-memory` и
`--variant full` выполняют один выбранный опыт. `--output` задаёт новый каталог.

Командные знания размещаются в `team_knowledge/`. Поддерживаются каталог с
`INDEX.md` и снимок с вложенным `knowledge/INDEX.md`. Индекс и каталог навыков этой
области подключаются при инициализации вместе с личной памятью.

## Подключение к циклу формирования памяти

```powershell
& $python -X utf8 consolidate_reports_openrouter.py `
  --user-id 101 `
  --workspace data/fc/20261025T182357Z-new-skills/w/101 `
  --reports-dir data/fc/20261025T182357Z-new-skills/r/101 `
  --stage personal `
  --model deepseek/deepseek-v4.1-flash-1017 `
  --evaluate-by-replay `
  --replay-scenario docs/examples/replay-anna/dialogue-scenario.json
```

В этом пути диалог проверяет уже подготовленный снимок. Следующий оценщик
сравнивает полученный результат с прежним по правилам публикации памяти.
Перед диалогом код проверяет наличие данных. При их нехватке принятие
основывается на review со статусом skipped; отдельной оценки стоимости нет.
Для отдельного сравнения двух вариантов используется `run_dialogue_replay.py`.

## Показатели и журналы

Результаты отдельного сравнения записываются в `data/dialogue-runs/<запуск>/`:

```text
scenario.json
comparison.json
comparison.md
no-memory/
  workspace/
  result/
    initialization.json
    chat_logs.db
    transcript.jsonl
    turns.json
    answer.md
    decisions.jsonl
    metrics.json
    tester/
      initialization.md
      transcript.jsonl
full/
  workspace/
  result/
    ...
```

`transcript.jsonl` содержит отправленные исходные реплики, ответы агента, вызовы
инструментов и их результаты. `tester/transcript.jsonl` содержит наблюдения
тестировщика и его ответы. `decisions.jsonl` хранит проверенные решения выбора
следующей реплики. `initialization.json` показывает модель, подключённые источники
памяти, каталоги навыков и настройки окружения.

В `metrics.json` блок `tested_agent` содержит затраты решающего агента, блок
`tester` — затраты имитируемого пользователя. Верхние поля `model_calls`,
`tool_calls` и `usage` относятся к решающему агенту для совместимости с существующим
сбором метрик. Полное время `duration_seconds` включает обе роли. Значение
`usage_complete` показывает полноту сведений о токенах, полученных от провайдера.

`turns.json` позволяет изучить время и затраты каждой пользовательской реплики.
Для сравнения полезно смотреть число потребовавшихся уточнений, время решения,
обращения к модели, действия инструментов, входные токены, сохранённую часть
входа, выходные токены и итог проверки конечной цели. Затраты на построение памяти
учитываются как отдельный процесс.

## Условия завершения

- `completed`: тестировщик подтвердил всю конечную цель по ответу и файлам.
- `inconclusive`: доступные исходные реплики исчерпаны либо цель требует дальнейших сведений.
- `turn_limit`: достигнут установленный предел пользовательских ходов.
- `failed`: ошибка модели, протокола, файлов или изменение защищённых исходников.

По умолчанию предел пользовательских ходов равен числу исходных реплик. Его можно
снизить через `--max-user-turns`. Предел шагов графа в одной реплике задаётся
через `--recursion-limit`, по умолчанию 1000. Один сетевой запрос ограничен 180
секундами; автоматические повторы отключены. Частичные сообщения и доступные
показатели сохраняются при ошибке.

Тестировщик получает новые и изменённые файлы после очередной реплики; прежние
наблюдения сохраняются в его контексте. Он получает до 120 000 символов текстовых результатов на ход; двоичные
файлы представлены метаданными. Предел меняется через `--artifact-text-limit`.
Каждое сокращение текста отмечено полем `truncated`.

Оценка достижения цели остаётся решением модели-тестировщика. Для научного
сравнения стоит проверять её решения по журналам и выполнять несколько пар
опытов: выбор уточнений и поведение решающей модели могут различаться.

Отдельные области изолируют размещение материалов и контексты моделей. Команда
`execute` выполняется с правами процесса Windows. Полная изоляция файловой
системы потребует отдельного процесса с ограничениями среды выполнения.
