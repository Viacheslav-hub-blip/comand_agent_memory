# Структура проекта по целевой схеме

Источники блока 1 сохранены. Учёт подтверждений, pending и conflicts блока 6
отложен по прямому указанию пользователя.

```text
command_agent_memory/
├── analysis/                   # Блок 2: новые сессии → два отчёта
│   ├── pipeline.py             # Выбор сессий, анализ, manifest
│   └── reports.py              # Техническая версия набора отчётов
├── memory/                     # Блоки 3, 5 и временный режим блока 6
│   ├── personal.py             # Копия → консолидация → review → принятие
│   ├── team.py                 # Принятые личные знания → общая версия и доставка
│   └── cli.py                  # Команды personal / knowledge / both
├── evaluation/                 # Блок 4: диалог и сравнение
│   ├── scenario.py             # Отдельные исходные пользовательские реплики
│   ├── dialogue.py             # Агент с новой памятью ↔ тестировщик
│   └── replay.py               # Наличие данных, копия окружения, итоговый оценщик
├── pipeline.py                 # Полный цикл для одного или нескольких пользователей
├── adapters/                   # Прежние исполнители Codex / OpenRouter
├── runs/                       # Уникальные каталоги запусков
└── synthetic/                  # Загрузка тестовых диалогов

run_memory_pipeline.py          # Основная CLI-команда
run_openrouter_pipeline.py      # Совместимая команда OpenRouter + источник Codex
analyze_chats_*.py              # Тонкие точки входа анализа
consolidate_reports_*.py        # Тонкие точки входа этапов памяти
reviewed_consolidation.py       # Совместимое имя memory.personal
replay_evaluation.py            # Совместимое имя evaluation.replay
memory_pipeline.py             # Чтение полных отчётов и экспорт SQLite
agent_runtime.py               # Сборка решающего агента и запись сообщений
codex_history.py                # Существующее чтение локальных логов Codex
agents/                        # Инструкции LLM отдельных этапов
tests/                         # Локальные проверки без моделей
```

## Границы этапов

analysis.pipeline не изменяет память. Завершённая пара отчётов подтверждается
manifest и наличием непустых файлов. Новые сессии обрабатываются отдельно;
исходный Markdown не разбирается по разделам. Необязательный лимит Codex
сохранён, но по умолчанию отбираются все ещё не обработанные сессии проектов.

memory.personal готовит одну копию правил, предпочтений, wiki и knowledge.
Только принятый review допускает проверку данных и последующую публикацию.
Проверка данных выполняется локально. Прогон в основном пути всегда диалоговый.
После него требуется завершённый результат и выбор candidate.

memory.team принимает опубликованные личные снимки after/, а не raw-отчёты.
Сверяет хеши принятой версии и экспортирует только knowledge/. Объединение
выполняется одним LLM-сеансом в копии, без дополнительного review. Неустранённое
противоречие останавливает публикацию всей командной копии. Реестр и частичный
отзыв спорных утверждений пока не реализованы.

Публикация сохраняет резервные копии и проверяет конкурирующие изменения.
Владельцы получают общую версию в workspace/team_knowledge/. Следующий сеанс
agent_runtime подключает существующий индекс и каталог skills.

## Повторное использование и расширение

run_memory_pipeline.py принимает одно задание либо --users с JSON-списком.
Проверка всех входных областей выполняется до модельных вызовов. Личные снимки
принимаются независимо; ошибка одного задания не откатывает уже опубликованные
личные версии других пользователей.

Обычный повтор без новых входов использует принятые результаты по техническим
хешам отчётов и памяти. Эти хеши не являются подтверждениями истинности знаний.
Явный --evaluate-by-replay выполняет новый личный цикл.

Новый исполнитель модели добавляется в adapters.registry через ModelAdapter.
Чтение логов и выполнение модели остаются разными ответственностями.
Подключения внешних агентов доступны через `--config`: источники Claude Code,
Codex, GigaAgent, Phoenix, JSONL и SQLite описаны в [agent-connections.md](agent-connections.md).
`configuration.py` задаёт модели этапов и пожелания; `history.py` содержит реестр
источников; `memory/store.py` обновляет настроенные файлы внешней памяти;
`connections.py` связывает их с существующей консолидацией и ревью.

Прежние одношаговые функции оценки и отдельные ablation-команды остаются для
исторических опытов. Основной CLI не предлагает force-replay, выбор replay-backend
или оценку стоимости перед проверкой данных.
