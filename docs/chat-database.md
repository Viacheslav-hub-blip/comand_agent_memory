# Хранение диалогов

База <workspace>/chat_logs.db хранит сообщения одного или нескольких пользователей.
Рабочая область для анализа и консолидации задаётся явно через --workspace.

## Таблица messages

| Поле | Содержание |
| --- | --- |
| id | Порядок записей |
| session_id | Диалог |
| user_id | Пользователь |
| created_at | UTC-время записи |
| role | user, ai, tool; в импортированных историях также transcript |
| content | Текст сообщения либо сериализованное содержимое |
| message_json | Полное сообщение, включая вызовы инструментов и usage при наличии |

agent_runtime.open_chat_database создаёт таблицу при её отсутствии и сохраняет
существующие записи. save_message фиксирует каждое сообщение сразу.
run_turn сначала сохраняет реплику пользователя, затем ответы и результаты
инструментов. При сбое уже полученные сообщения остаются в базе.

Консольный агент использует user_workspace/chat_logs.db. Синтетическая команда
использует отдельную базу каждого участника в data/synthetic-team-runs/<запуск>/users/.
У каждого диалога новый session_id; вызовы с тем же session_id продолжают контекст.

## Анализ

```powershell
python analyze_chats_codex.py --user-id 101 --workspace data/synthetic-team-runs/20261020T040159Z-a0d71f0d/users/101/user_workspace
```

Код открывает SQLite в mode=ro, фильтрует по user_id и session_id, упорядочивает
сообщения по id и выгружает полный JSONL для отдельного процесса анализа.
Совпадающий с message_json текст content второй раз не записывается.
Анализатор получает готовую историю; ему не нужно самостоятельно читать SQLite.

Отчёт: <workspace>/raw/chat-reports-codex/session-<id>.md.
[Консолидация отчётов](memory-pipeline.md) запускается отдельно.

Старые импортированные истории сохранены целиком с ролью transcript.
Исходные изображения портфеля в data/portfolio-images/ остаются данными этих
историй; удаление прежнего Phoenix-кода не является основанием удалять изображения.
