## Метод и повторная применимость

`reconciliation.sql` разбит на именованные блоки, повторяющие ваши пять этапов, и **параметризован** — конкретные даты и суммы в текст запросов не зашиты:

| Этап | Блоки |
|---|---|
| 1. Определения и периоды | `01_definitions_periods` |
| 2. Гранулярность | `02_granularity_check`, `03_granularity_summary` |
| 3. Согласованный срез | `04_decision_snapshot` |
| 4. Сравнение компонент | `05_approved_on_snapshot`, `06_approval_rate`, `07_final_decision_approval_rate`, `08_money_components` |
| 5. Объяснение остатка | `09_legacy_query_as_is`, `10_residual_decomposition`, `11_residual_totals` |

Параметры: `:cohort_lo`, `:cohort_hi`, `:as_of`, `:include_test`. Для другой когорты меняются только аргументы запуска:

```
python run_reconciliation.py --cohort-lo "2026-09-01 00:00:00" --cohort-hi "2026-10-01 00:00:00" --as-of "2026-10-03 00:00:00" --definition v1
```

Остаток объясняется не фиксированными суммами, а классификацией по корзинам (`in_both`, `legacy_extra_status`, `legacy_extra_test`, `snapshot_only`), поэтому работает на любой когорте. Проверил оба определения: `--definition v1` даёт 3/27 000/47 000/23 000/24 000, `--definition v2` — 2/22 000/42 000/23 000/19 000.
