# C01. Анна: почему не сходится отчёт

Оператору: user_id=101, новый сеанс. Сценарная дата 3 октября. Не передавайте этот заголовок или эталон. Четыре блока — четыре последовательные пользовательские реплики. Все суммы и правила вымышлены.

## Реплика 1

```text
Я Анна, бизнес-аналитик команды «Север». Разбираю отчёт по заявкам за 1–2 октября 2026. Мне удобно сначала видеть короткий вывод, затем таблицу расхождений; для сверок предпочитаю SQL. Прочитай /synthetic_team/documents/reporting_v1.md, /synthetic_team/documents/data_dictionary.md и /synthetic_team/sql/legacy_approval.sql. Данные лежат в /synthetic_team/inputs/. Проверь, почему сумма одобренных заявок из старого запроса не совпадает с чистой выдачей. Нужен исторический срез знания на 2026-10-03 00:00:00 UTC. Сначала покажи, какие величины вообще сопоставимы и что проверишь; затем можешь посчитать локально. Сети и подключений к реальным БД нет.
```

## Реплика 2

```text
Уточню бизнес-смысл: «одобрение» у нас означает решение по заявке, а «выдача» — движение денег. Запрошенная сумма ещё не означает, что столько перечислили. Заявочная когорта определяется временем регистрации, а денежные события — временем проведения. Я не ожидаю равенства этих сумм, хочу объяснимую сверку. Проверь ещё, не размножаются ли заявки при соединении с историей решений.
```

## Реплика 3

```text
Теперь выполни расчёт на CSV. Если нужен SQLite, создай отдельную локальную базу по /synthetic_team/sql/schema.sql внутри /synthetic_team/outputs/C01/ и загрузи CSV через стандартный Python. Для текущего отчёта сохраняем именно v1, тестовые заявки пока входят. Покажи число заявок, одобренные заявки на срез, сумму по ним, выдачи, возвраты и чистую выдачу. Дай короткую таблицу причин расхождений; исходные файлы не меняй.
```

```text
Оформи результат и воспроизводимый SQL в /synthetic_team/outputs/C01/. Завтра придётся делать такую же сверку для другой когорты, поэтому не зашивай в объяснение только эти суммы и даты.
```
