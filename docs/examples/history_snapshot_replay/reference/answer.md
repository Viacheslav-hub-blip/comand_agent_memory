# Эталонный результат Бориса C02

Результат сохранён в `/synthetic_team/outputs/C02/`, исходные файлы не изменены.

Исторически известное состояние фильтрует события по `occurred_at < T AND loaded_at < T`.
Пересчёт прошлого использует прежнюю границу `occurred_at < T`, но не ограничивает
`loaded_at`. В обоих режимах последняя запись выбирается через
`ROW_NUMBER() OVER (PARTITION BY application_id ORDER BY occurred_at DESC, event_id DESC)`.

После выбора среза должна оставаться одна строка на заявку. `LEFT JOIN` должен
сохранять восемь заявок когорты; потерянных заявок, заявок вне когорты, пустых ключей
и неоднозначных ключей порядка быть не должно. Исходное соединение имеет fan-out:
13 строк на 8 заявок.

Режимы различаются на A006: на историческом срезе поздно загруженное событие ещё не
известно, а при пересчёте прошлого оно учитывается. A007 разрешается по большему
`event_id` при одинаковом `occurred_at`; статус нельзя выбирать по алфавиту.

`DISTINCT application_id, requested_amount_rub, status` не устраняет историю:
разные статусы одной заявки остаются разными строками. Удаление статуса либо замена
его на `MAX(status)` может дать одну строку, но теряет временную семантику. Поэтому
нужны одновременно проверка кардинальности и проверка выбора правильного события.

Воспроизводимый комплект включает параметризованный SQL, локальную SQLite-базу,
скрипт запуска и автоматические проверки уникальности и сохранности количества строк.
