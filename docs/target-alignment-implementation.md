# Приведение реализации к утверждённой схеме

Дата: 26 октября 2026 года.

По уточнению пользователя сохранены источники блока 1. Постоянный реестр
подтверждений, pending и conflicts блока 6 отложены целиком. Выполняется
объединение принятых личных знаний без этого механизма.

## Изменения

- Основной цикл: `command_agent_memory/pipeline.py`, команда `run_memory_pipeline.py`.
- Блок 2: `analysis/pipeline.py` отбирает необработанные сессии, создаёт два
  отчёта и не повторяет готовые пары. Без явно заданного лимита Codex берутся
  все сессии выбранных проектов. Форматы существующих источников сохранены.
- Блок 3: `memory/personal.py` содержит прежние механизмы копии, двух
  консолидаторов, исправляющего review и публикации с резервированием.
- Блок 4: `evaluation/replay.py` проверяет наличие запроса, отдельных реплик,
  входных файлов и прежнего ответа. Данных нет — skipped и принятие по review.
  Данные есть — диалог и отдельный оценщик; перенос разрешает только candidate.
- Блок 5: один запуск принимает JSON-список пользователей и выполняет личные
  циклы независимо. Пересекающиеся области и чужой владелец в manifest запрещены.
- Блок 6: `memory/team.py` читает только принятые личные снимки after/ с
  проверенными хешами. В командную модель передаётся knowledge/, без личных
  AGENTS.md, USER_PREFERENCES.md и user_llm_wiki/. Дополнительного review нет:
  один консолидатор объединяет знания и возвращает решение. При неразрешённой
  проблеме общая версия сохраняется. Подтверждения и голосование не имитируются.
- После командной публикации team_knowledge/ обновляется в рабочих областях
  владельцев. Существующий agent_runtime подключает его в новом сеансе.

Прежние корневые команды анализа и консолидации стали тонкими точками входа.
Импорты reviewed_consolidation и replay_evaluation сохранены через тот же модуль
подсистемы. Флаги force-replay, replay-backend и agent-python удалены из основного
CLI. Отдельные экспериментальные методы и команды остаются вне основного пути.

Сценарий Codex теперь содержит весь список исходных реплик, первую реплику как
request и последний результат как эталон. Сценарий не перезаписывает существующий
каталог. Отсутствие материалов отличается от ошибки чтения или повреждённого JSON.

## Повторный запуск

В status.json сохраняются владелец, состояние публикации, статус прогона,
хеши принятого снимка и версия аналитических входов. Обычный повтор с
неизменными входами использует уже принятый результат. Явно запрошенная новая
проверка не подменяется прежним принятием без прогона.

Эти записи обслуживают повторный запуск и проверку файлов. Они не являются
реестром независимых подтверждений утверждений.

## Проверки

- Исходный набор до изменений: 98 тестов, один пропуск.
- Полный набор после основного изменения: 106 тестов за 62.237 с, один пропуск.
- После дополнительной проверки владельца отчётов: 31 адресный тест за 27.278 с,
  все прошли. Проверены входы отчётов, анализ, личное принятие и сквозной цикл.
- Полные и адресные финальные проверки выполнялись с запретом socket-соединений.
- Сквозной тест проверяет двух пользователей, единственный командный вызов,
  изоляцию личных правил, повтор без модельных вызовов, отказ review, skipped,
  изменение принятого снимка и отсутствие командных знаний.
- Синтаксис новых модулей, наличие docstrings и справка основных CLI проверены.

В первой версии нового сквозного теста подмена одного исполнителя была ошибочной:
OpenRouter получил запросы с фиктивным ID модели test и отклонил их с кодом 400.
Подмена исправлена; в тест добавлен запрет сети. Полноценный прогон на реальной
модели и оценка качества сформированной памяти в этой работе не выполнялись.

## Ограничения

Нативные адаптеры Claude Code/GigaCode и доставка им знаний не добавлены.
Существующие источники SQLite/Codex и подключение в agent_runtime сохранены.
Частичный отзыв спорного утверждения, независимые подтверждения и повторное
рассмотрение по постоянному реестру остаются будущей реализацией.

Исторические документы и результаты не переименовывались в результаты новой
методики. Опубликованные пользовательские и командные знания в рабочем проекте
реальными моделями не переформировывались.
