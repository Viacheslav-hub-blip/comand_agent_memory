# Диалоговая проверка памяти

Проверка выполняется только как часть конвейера:

```powershell
python -m command_agent_memory --config memory_pipeline.json --evaluate-by-replay
```

Укажите `replay_scenario` у пользователя в JSON-конфигурации. Для модельных ролей
настройте этапы `replay_agent`, `replay_tester` и `evaluation` либо общие defaults.

В диалоге участвуют два отдельных экземпляра модели. Решающий агент получает
исходные пользовательские реплики и рабочую копию с новой памятью. Тестировщик
видит цель, исходный диалог и эталон; после каждого ответа выбирает следующую
исходную реплику или подтверждает достижение цели. Эталон не передаётся решающему агенту.
Завершённый результат сравнивается с прежним ответом отдельным оценщиком.

## Сценарий

```json
{
  "messages": ["Проверь расхождение отчёта", "Сохрани результат в report.md"],
  "goal": "Объяснить расхождение и сохранить проверенный отчёт",
  "inputs": "inputs",
  "reference": "reference"
}
```

`inputs` содержит исходные файлы, `reference/answer.md` — прежний ответ.
Все материалы должны находиться в каталоге конфигурации либо его подкаталогах.
Каталоги исходных данных и эталона должны быть раздельными.
Вместо `messages` можно задать `dialogue_source` — путь к Markdown с исходными
репликами в блоках text. `request`, если задан, должен точно совпадать с первой
репликой. Необязательный `reference_metrics` хранит исходные измерения.

Первое сообщение передаётся дословно. Тестировщик выбирает следующие исходные
реплики по индексам; повторный или обратный переход останавливает проверку.
Для завершения требуется явное подтверждение конечной цели. Лимит ходов и сбой
не считаются успешным решением.

## Принятие и журналы

Наличие данных проверяется локально, без модели. Если сценария, реплик или
прежнего ответа не хватает, проверка получает `skipped`, а память принимается
по ревью. Повреждённые материалы вызывают ошибку.

При выполненном диалоге публикация разрешается только при выборе `candidate`.
Выбор `current`, `inconclusive`, изменение памяти решающим агентом или сбой
останавливают публикацию. Модельная оценка стоимости прогона не используется.

Материалы находятся в `workspace/consolidation-runs/<ID>/personal/replay/`:
рабочая копия, эталон, ответ, файлы результата, трасса, измерения и decision.json.
Неизвестные измерения остаются null. Защита памяти и проверка изменения исходных
данных выполняются дополнительно к модельным решениям.

Реализация: `command_agent_memory/memory_replay/`. Проверки:
`tests/test_dialogue_replay.py`, `tests/test_replay_evaluation.py` и проверки
настроенного диалога в `tests/test_memory_pipeline.py`.
