# Консолидация личной памяти

## Назначение и вход

Обнови личную память пользователя по предоставленным сведениям и текущему состоянию разрешённой рабочей копии. Сохрани полезный для будущей работы контекст с точной областью и статусом. Редактируй только разрешённые файлы.

Вход: извлечённые сведения, текущие `AGENTS.md`, `USER_PREFERENCES.md`, данные `user_llm_wiki/`, разрешённый рабочий каталог. Для неизвестного расположения нужной статьи используй локальный индекс, когда он существует. Сначала читай затронутые разделы; расширяй область чтения при обнаруженном конфликте или явном запросе общей ревизии.

Сведения для сохранения берутся из извлечённых отчётов и подтверждённой прежней
памяти. Описание ОС, Python, shell и путей в текущем задании описывает среду
консолидатора. Разрешённые пути записи, роль этапа и инструкции по работе с его
копией являются служебным протоколом. Они не являются новыми фактами о рабочем
агенте пользователя и не сохраняются в AGENTS.md или wiki. Для каждого нового
правила об окружении требуется основание именно в извлечённых сведениях.
Уже попавшие в память указания о текущем служебном сеансе консолидации убери,
сохранив подтверждённые пользовательские правила для его собственной среды.

## Границы файлов

- **`AGENTS.md`**: устойчивые общие инструкции агенту, применимые в нескольких задачах или проектах или несколькими пользователями. Сюда же помещай правила исполнения рабочей области пользователя, подтверждённые извлечёнными сведениями: ОС и shell, отображение виртуальных путей, команда интерпретатора и права доступа; указывай область их действия. Служебные правила текущего консолидатора не переносить.
- **`USER_PREFERENCES.md`**: устойчивый выбор пользователя в общении, инструментах, коде и формате результата; указывай класс задач, если выбор локален.
- **`user_llm_wiki/`**: цели, системы, окружение, роли, актуальные возможности, рабочие соглашения и состояние конкретных проектов. Здесь описывай факты и ресурсы, необходимые для продолжения.

Предметные определения, исторические способы решения задач и универсальные рабочие алгоритмы не являются самостоятельными объектами редактирования в этой личной памяти. В проектной статье допустимо краткое описание существующего решения и назначения файла, если это помогает ориентироваться в продолжающемся проекте.

## Выполнение

1. **Нормализуй новые сведения.** Выдели утверждения, проект, статус, версию, временной контекст и область действия. Сохраняй только сведения, которые вероятно потребуются после завершения текущей реплики.
2. **Сопоставь с существующей записью.** Установи: повтор, уточнение, смена состояния, новая область, конфликт или устаревшая информация. При равном смысле исправь существующий пункт, а не создавай дубликат.
3. **Распредели по месту.** Общие инструкции и предпочтения размещай в корневых файлах лишь при подтверждённой устойчивости. Параметры конкретного запуска и временный запрет сохраняй только для незавершённой работы, где они сохраняют действие.
4. **Внеси минимальные изменения.** Обнови точный фрагмент. Создавай новую статью только для самостоятельной темы, которая иначе потеряется в существующей; индексируй её локальным путём.
5. **Разреши известные исправления.** Сохраняй подтверждённое актуальное состояние вместо прежнего, если новая информация явно его заменяет. При конфликте без разрешения оставь доказанную часть и вынеси вопрос в итог.
6. **Проверь итог.** Перечитай изменённые разделы и связанные пункты. Убедись, что новые указания не стали глобальными без оснований, а длинные процедуры и исторические неудачные команды не заполнили проектную wiki.

## Точность и экономия

- Записывай сведения автономно, без пересказа беседы, ссылок на исходные чаты, номеров сообщений, идентификаторов трасс и журнала проверки.
- Указывай имя поля, путь, версию и дату, если они нужны для следующего действия. Различай **исторически созданный файл** и файл, доступный сейчас; факт прошлой записи не гарантирует наличие ресурса в новом окружении.
- Сохраняй существенное различие между реализованным, запланированным, отменённым и гипотетическим.
- Объединяй повторяющиеся детали, сохраняя фактическую конкретику. В `AGENTS.md` не дублируй предметные инструкции из проектной статьи.
- Для будущего выполнения сохраняй правила полномочий и безопасный способ работы с путями. Компактно записывай стабильные параметры окружения один раз для соответствующей рабочей области. Команду `python` и правило разрешения виртуальных путей применяй в пределах подтверждённого окружения; изменение текущей директории, ОС или оболочки требует актуализации записи.
- Дополнительные отчёты, тесты и файлы связывай с текущим запросом или необходимой проверкой правильности. Сохраняй конкретные исполнимые алгоритмы в предметных инструкциях, а сведения о доступе и правах — в общих инструкциях.
- Исключай секреты, учётные данные и избыточные личные подробности.

## Пример преобразования: сведения → точечные изменения файлов

Вход:

```text
- «Для сверок предпочитаю SQL с именованными CTE».
- «Обычно Python — pandas; сегодня пакеты не устанавливать».
- «В рабочей области команды "Север": Windows cmd; Python — python;
  /synthetic_team в файловых инструментах виртуален; в Python
  разрешай его через Path.cwd() / "synthetic_team";
  /user_llm_wiki/ доступна только для чтения».
- «В прошлый раз создан outputs/C02/findings.md».
```

Сохрани изменения в соответствующих местах:

```markdown
# AGENTS.md — раздел «Рабочая область Север»
- Используй Windows cmd для команд в этой рабочей области.
- Запускай Python командой `python` и разрешай пути к проекту
  относительно `Path.cwd() / "synthetic_team"`.
- Считай `/user_llm_wiki/` доступной только для чтения.

# USER_PREFERENCES.md
- Для аналитических SQL-сверок пользователь предпочитает
  именованные CTE и явный перечень колонок.
- Для Python-аналитики обычно предпочитает pandas.

# user_llm_wiki/sever-project.md
- В предыдущем запуске был создан `outputs/C02/findings.md`;
  наличие файла в новой рабочей области требует проверки.
```

Разовое «сегодня пакеты не устанавливать» сохраняй лишь в контексте незавершённой работы. При одинаковых сведениях в уже существующих разделах уточняй запись, сохраняя одну актуальную формулировку.

## Результат и завершение

Внеси правки в разрешённую копию. Ответь кратко обычным текстом: изменённые файлы и смысл правок, нерешённые конфликты; при отсутствии изменений укажи, что память уже отражает новые сведения.

Заверши после проверки затронутого контекста и внутренних ссылок. Дополнительная перестройка личной wiki требуется при реальном конфликте, дублировании или прямом запросе пользователя. Для неоднозначных ситуаций смотри [примеры размещения](references/examples.md).
