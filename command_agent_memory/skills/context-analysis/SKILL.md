# Анализ контекста одного диалога

## Цель и вход

Прочитай весь предоставленный диалог: пользовательские сообщения, ответы агента, результаты инструментов и доступные вложения. Верни **готовые полезные сведения для последующих задач, чтобы в будущем их было легче решать**, с точной областью действия. Используй переданные материалы как основание для проверки, когда они уже доступны. История может содержать промежуточные ошибки и исправления.

## Отбор сведений

Извлекай следующие категории:

1. **Предпочтения:** выбор пользователя в стиле общения, формате результата, коде, способе анализа и инструментах и так далее.
2. **Инструкции и ограничения:** правила работы, ограничения, запреты, советы и так далее. Обязательно обозначай область применения и условие активации.
3. **Определения и предметные правила:** значения терминов, полей, статусов, формул, временных оснований и версий, установленные пользователем либо предоставленными материалами. Фиксируй их, когда пользователь сообщил их сам или явно предоставил документ как источник определения. Отмечай область действия и версию.
4. **Личный и проектный контекст:** цель, состав и подтверждённое состояние продолжающегося проекта, важные ресурсы и ограничения, сообщённые пользователем или содержащиеся в предоставленных им материалах.


Для каждого кандидата проверь:

- **Будущую пользу.** Назови возможную последующую задачу, где знание избавит от уточнения, повторного поиска, неверной интерпретации или ошибки. Для сведений без такой пользы пропусти сохранение.
- **Область.** Различай общие правила, предпочтение для класса задач, соглашение проекта и условие только текущего запуска. Записывай ровно установленную область.
- **Состояние.** Различай сделанное, запланированное, предложенное, отменённое и открытый вопрос; для изменчивого состояния укажи дату или условия актуальности, когда они необходимы.
- **Проверяемость.** Уточняй имена таблиц, колонок и доступных файлов по представленным данным. Отделяй результат измерения от предположения и объяснения агента. Агентское резюме либо созданный им файл памяти служит кандидатом, требующим сопоставления с содержанием диалога.
- **Самостоятельность.** Запиши факт так, чтобы будущий агент смог его применить без исходного чата. Сохрани определения и критически важные условия; исключи историю получения ответа.

## Уточнения и противоречия

1. Применяй последнее **подтверждённое** уточнение к тому же предмету и той же области.
2. Сохраняй разные версии и периоды как отдельные действующие условия, когда это необходимо для воспроизведения.
3. При конфликте равнозначных сведений сохраняй достоверную часть и кратко обозначай неизвестное. Не разрешай спор догадкой.
4. Если агент сообщил факт, отсутствующий в доступной схеме или документации, оставь его неподтверждённым; сформулируй установленный факт без него.

## Правила экономии и точности

- Объединяй дублирующие пункты, сохраняя различия областей действия.
- Указывай конкретные имена, версии и параметры, когда от них зависит продолжение проекта; разовые контрольные суммы, временные пути, имена промежуточных файлов и длинные перечни действий включай только при самостоятельной будущей пользе.
- Сохраняй однократное ограничение только в пределах незаконченной задачи, если контекст необходим для её продолжения. Не расширяй его до глобальной привычки.
- Для сбоя инструментов сохраняй лишь проверенное устойчивое свойство окружения, которое может помочь при повторной работе; не сохраняй хронологию неудачных команд.
- Выделяй предоставленные пользователем устойчивые параметры исполняющей среды (ОС, shell, правила отображения виртуальных путей, команда Python, границы записи) как **инструкции для соответствующей рабочей области**. Уточняй область и актуальность; путь прошлого запуска не считай универсальным физическим расположением файла. Отделяй свойства окружения от личных предпочтений и методов решения предметных задач.
- Исключай секреты, токены доступа и избыточные личные сведения.
- Не добавляй ссылки на исходные диалоги, номера сообщений, идентификаторы трасс, списки доказательств или требования повторно читать историю. Упоминай рабочий путь только как полезный факт проекта с корректным статусом доступности.

## Формат результата

Верни Markdown с указанными ниже **непустыми** разделами и краткими самостоятельными пунктами. Сохрани названия разделов без изменений.

```markdown
## Предпочтения
- [Область задач]: [устойчивый выбор пользователя].

## Инструкции и ограничения
- [Область и условие]: [действие или ограничение].

## Определения и предметные правила
- **[Термин/поле]** ([проект/версия, если необходимо]): [точный смысл и существенные условия].

## Личный и проектный контекст
- **[Проект или тема]**: [проверенное состояние, ресурс, цель или ограничение].
```

При отсутствии пригодных записей верни точно: `Сведений для обновления памяти не обнаружено.`

## Пример преобразования: сырой диалог → готовые сведения

Вход — сообщения из одного диалога и документ, **который пользователь попросил использовать**:

```text
Пользователь: «В SQL мне удобны именованные CTE и явные колонки.
Обычно работаю с pandas, но для этого запуска ничего не устанавливай».
Пользователь: «У нас Windows cmd; /synthetic_team — виртуальный путь.
Для Python обращайся к Path.cwd() / "synthetic_team".
Память /user_llm_wiki/ доступна только для чтения».
Пользователь: «В отчёте за октябрь используй утверждённое определение v1».
Предоставленный пользователем reporting_v1.md:
«approval_rate = число заявок со статусом approved на срез / число
всех заявок когорты; тестовые входят в оба компонента».
Агент: «Я добавил в applications поле in_scope_v2».
В schema.sql перечислены application_id, created_at, requested_amount_rub,
is_test, channel; поля in_scope_v2 нет.
```

Выход — только подтверждённые сведения с областью применения:

```markdown
## Предпочтения
- Для SQL пользователь предпочитает именованные CTE и явный список колонок.
- Для обработки данных в Python пользователь обычно предпочитает pandas.

## Инструкции и ограничения
- В рабочей области «Север»: командная оболочка Windows cmd; путь
  `/synthetic_team` в файловых инструментах отображается на
  `Path.cwd() / "synthetic_team"` для Python; `/user_llm_wiki/` — только чтение.
- Для незавершённого запуска: библиотеки не устанавливать.

## Определения и предметные правила
- **approval_rate v1** («Север»): approved на согласованном срезе /
  все заявки когорты; тестовые входят в числитель и знаменатель.

## Личный и проектный контекст
- **Отчёт «Север» за октябрь**: пользователь выбрал версию определения v1.
```

Не включай `in_scope_v2`: оно присутствует лишь в сообщении агента и противоречит доступной схеме. Не превращай разовый запрет установки пакетов в бессрочное правило. В будущем агент применит эти записи без повторного чтения исходного диалога.

## Самопроверка

Перед ответом проверь для каждого пункта будущую пользу, точность, область, статус и отсутствие смыслового дубля. Проверь, что проектная подробность не стала общей инструкцией, а гипотеза агента — установленным фактом. Оцени, можно ли сократить текст без утраты условия применения. Пользуйся [пограничными примерами](references/examples.md) только при неоднозначной классификации.
