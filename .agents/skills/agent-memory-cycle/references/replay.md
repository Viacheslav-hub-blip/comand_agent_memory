# Две независимые сессии

Запрошенный replay требует исходных messages, inputs и reference/answer.md.
Сценарий указывается через users[].replay_scenario. Выполни `io replay-inputs
--config C --user U --run R`. Получишь путь к двум рабочим копиям и закрытым
материалам проверки. Для каждой копии используй штатный harness решающего агента.

Запусти две свежие сессии без истории родителя с одинаковой моделью,
инструкциями и инструментами. Каждой дай только её workspace и первую дословную
реплику. Зафиксируй фактические разные ID и одинаковые профили до первого хода.
Профиль содержит model, model_parameters, system_prompt_sha256, implementation,
environment и tools. У инструмента нужны name, schema и implementation. Хеш
одинакового стартового текста вычисли средствами ОС. При невозможности получить
сопоставимые сессии останови проверку.

Отдельному **replay-tester** для каждой стороны передай цель, список реплик,
эталон и результаты её ходов. По send продолжай исходную сессию указанной
репликой. По complete или stop сохрани фактический итог. Рабочие агенты
получают только свои входы и реплики. Сохрани в `R/replay/{baseline,candidate}/result.json`
объект с session_id, profile, state (completed, inconclusive или turn_limit) и
turns. Каждый ход содержит message_index (от 1), user и answer. Сохрани доступные
измерения отдельно; отсутствующим значениям соответствует null.

Передай независимому **replay-evaluation** оба результата, изменённые файлы,
эталон и измерения. Его исходный JSON с choice и summary запиши в
`R/replay/decision.json`. При current, inconclusive, изменении входов или
несовпадении профилей заверши цикл без публикации. При candidate вернись к publish.
