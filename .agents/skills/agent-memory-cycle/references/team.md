# Командная обработка

Для локального team.root передай принятые личные журналы: `io team-input
--config C --accepted R1 R2`. Для Git участник выполняет `io team-submit
--config C --accepted R1 R2`. Исполнитель читает очередь через `io team-input
--config C`; для отдельного ID запроси материалы с `--contribution ID`.

При назначенном фоновом исполнителе роль участника заканчивается отправкой вклада.
Участнику показывай его ID и статус из `io team-status --config C` с его cache_dir.
При applied различай принятое знание и запись pending/conflicts по полю knowledge.
Для needs_resolution покажи resolution, когда квитанция содержит объяснение.

Вызови **team-memory-consolidation**. Передай ему registry, sources и documents
из результата. Каждая новая запись должна ссылаться на существующий source-ID,
сохранять условия применения и объяснять основание. Сохрани объект
`{"input_sha256":"полученный хеш","result":{...}}`, где result — полный JSON
самого консолидатора. Хеш привязывает это решение к версии реестра и входов.

Выполни `io team-apply --config C --decision D` с теми же `--accepted` либо
`--contribution`. При изменении основания снова получи материалы и новое
решение. При повторной обработке Git учитывает квитанцию предыдущего применения.
Для доставки выполни `io team-sync --config C`. Получатели берутся из
team.workspaces. При локальном team.root доставка применяется после принятия.
Для Git сообщи commit и состояние синхронизации каждого получателя.
