# Режимы проверки и командной памяти

Справка описывает флаги запуска, требования replay и результат. Функций нет.

Статус собственных вкладов читает `--team-status` с конфигурацией отправителя.
Покажи состояние квитанции, актуальные статусы знаний и причину уточнения.

- `--team-process` обрабатывает вклады по Git-конфигурации, `--team-sync`
  получает канонический снимок. Используй их по запросу пользователя. В режиме
  синхронизации конвейеру достаточно штатного Git. Обычный запуск с настроенной
  командой выполняет предусмотренные конфигурацией действия для принятой памяти.
- `--evaluate-by-replay` в скилле включает обязательную проверку через Codex.
  Задания тестировщика и судьи передаются штатным субагентам, а два участника
  сравнения запускаются отдельными сессиями Codex. При неполных входах запуск
  останавливается до модели и публикации.
- Все режимы принимают `--validate-only`. Для явно настроенных провайдеров
  отдельного конвейера можно использовать штатный `python -m command_agent_memory`.
  В режиме субагентов значение `--model` записывается в журнал. Модель и число
  вызовов исполнителя контролирует клиент. Тайм-аут задаётся `timeout_seconds`.

## Replay в Codex

Для одного участника сначала проверь `--scenario <путь>`, затем `replay_scenario`
в конфиге и `replay_scenario.json` в корне проекта. Для нескольких участников
укажи `replay_scenario` отдельно для каждого. Без готового сценария подготовь JSON
из предоставленных пользователем `messages`, `goal`, каталога `inputs` и `reference` с
`answer.md`. Сохрани исходную первую реплику дословно. Если данных нет, сообщи,
какие входы нужны. Поле `agent` в этом режиме не требуется.

- `replay_start`. Запусти свежего субагента Codex **без истории родителя** и
  используй общий шаблон из `prompt`. Передай только его `workspace` и границы
  `memory_paths`. Проверь, что ему доступны обычные инструменты для этой задачи.
  Для второй сессии выбери те же модель, параметры и набор инструментов.
  Верни JSON с фактическим ID сессии `session_id` и `profile` со следующими
  полями. `model` — известная модель или `host-default` при одинаковом
  наследовании. `model_parameters`, `environment` — объекты фактических настроек
  запуска без секретов; `implementation` — строка исполнителя; `tools` — список
  его инструментов с `name`, `implementation` и `schema` (объект, пустой если хост
  не показывает схему). В `system_prompt_sha256` скопируй `instructions_sha256`
  из задания, это хеш общего шаблона данного прогона. Профиль описывает наблюдаемые
  настройки запуска. Если хост сообщает о смене модели или не даёт запустить или
  продолжить независимую сессию, верни `--error`.
- `replay_turn`. Продолжи сессию по `session_id`, передай ровно реплику из `prompt`.
  Рабочий агент читает файлы только из своей копии; сохраняет результаты задачи
  внутри неё и оставляет входные данные и память как есть. Не передавай ему эталон,
  критерии судьи, данные второй копии или историю, по которой обновлялась память.
  Верни JSON с `session_id` и `answer`, содержащим финальный ответ рабочего агента.
- Когда появляется `<tasks>/close-*.json`, закрой указанную сессию. Эти файлы
  уведомляют о закрытии и не требуют ответа. Дождись итогового JSON конвейера.

Профили сравниваются до первого хода. Повтор ID или различие профилей останавливает
публикацию. Метрики, которые клиент не передаёт, остаются `null`. В исходном CLI
внешний агент по-прежнему подключается через `agent.factory` сценария.
