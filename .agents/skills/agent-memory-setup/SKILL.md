# Подключение истории к Agent Memory

Скилл проверяет источник истории и сохраняет настройки проекта. Функций в файле нет.

Определи корень рабочего проекта и клиент, в котором пользователь ведёт нужные
диалоги. Используй Python 3.11+ и абсолютный путь к
[`scripts/setup_memory.py`](scripts/setup_memory.py). Ниже `setup` означает
`python -B -X utf8 <путь к setup_memory.py>`.

1. Если в корне уже есть `memory_pipeline.json`, проверь его командой
   `setup check --project <корень>`. Рабочий конфиг используй как есть.
   Если нужна перенастройка, сохрани настройки памяти, моделей, команды и
   остальных участников. Проверь исправленный вариант до применения.
2. Для нового подключения выполни `setup discover --project <корень> --host <клиент>`.
   Используй `codex` для Codex, `claude` для Claude Code, `gigacode` для
   GigaCode CLI и `gigaagent` для GigaAgent. Если клиент уже известен, не
   переспрашивай. Для известного пути добавь `--history <путь>`, а если формат
   отличается от штатного журнала клиента, укажи `--source codex|claude|jsonl|gigaagent`.
3. Если проверка не прошла, выясни, существует ли сохранённый чат этого проекта
   и доступен ли он из текущей среды. Спроси путь или формат только если их
   не удалось определить. Для настройки записи, экспорта или GigaAgent API
   используй [подключение журналов](references/history.md). После короткого
   тестового диалога повтори проверку.
4. Сохрани объект `configuration` из вывода в отдельный временный JSON.
   При подключении GigaAgent по API возьми готовый шаблон из справки.
   Относительные пути в кандидате считаются от корня проекта. При первом
   подключении выполни `setup save --project <корень> --config <кандидат>`.
   Команда проверяет чтение и создаёт `memory_pipeline.json`. Для существующего
   конфига сначала выполни `setup check --project <корень> --config <кандидат>`,
   затем примени согласованное изменение к исходному файлу и проверь его снова.

Модель для нативных скиллов выбирает клиент. Этот шаг проверяет источник и
сохраняет конфиг. Обновление памяти запускается отдельным запросом через
`agent-memory-cycle` или `update-agent-memory`. Покажи источник, сколько сессий
прочитано, путь к конфигу и пример следующего запроса. Содержимое диалогов для
отчёта о подключении не требуется.
