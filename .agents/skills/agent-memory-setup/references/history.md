# Как подключить журналы разных клиентов

Справка описывает поиск, запись и экспорт истории. Функций и классов нет.

## Codex и Claude Code

- **Codex.** Скрипт ищет rollout в `$CODEX_HOME/sessions` или
  `~/.codex/sessions`. Для другого каталога или файла укажи `--history`.
  Если пользователь работал в несохраняемой сессии, помоги открыть обычную
  локальную сессию в нужном проекте, сделать один тестовый обмен и проверить
  новый rollout. Настройки `history.jsonl` и экспорт вывода `codex exec --json`
  не заменяют rollout. [Справка Codex](https://developers.openai.com/codex/config-reference)
- **Claude Code.** Скрипт ищет транскрипты в `$CLAUDE_CONFIG_DIR/projects` или
  `~/.claude/projects`. Для собственного каталога или файла передай `--history`.
  Если сохранение выключено через `--no-session-persistence` или
  `CLAUDE_CODE_SKIP_PROMPT_HISTORY`, помоги открыть тестовую локальную сессию
  с сохранением истории. [Справка Claude Code](https://code.claude.com/docs/en/cli-reference)

По умолчанию настройки для этих клиентов заново находят последнюю сессию по
рабочему каталогу проекта при каждом обновлении. Явный путь к одному файлу
ограничивает поиск этим файлом. Если пользователю нужен конкретный прежний чат,
можно задать источник с путём к файлу и `session_ids` вместо `latest_in_project`.
Для облачной среды, которой недоступен локальный журнал, используй экспорт,
который пользователь может передать в рабочую среду.

## GigaAgent

Для локального экспорта выбери `--host gigaagent --history <файл>`. Контейнер
экспорта содержит `{"threads":[{"thread_id":"ID","history":[...]}]}`, где
`history` — полный список `ThreadState` выбранной ветки. Для API используй
следующий кандидат или перенеси из него только `source` в существующий конфиг:

```json
{
  "users": [
    {
      "user_id": "local",
      "workspace": ".agent-memory/runs",
      "source": {
        "type": "gigaagent",
        "url": "http://localhost:9090/api",
        "thread_ids": ["THREAD_ID"],
        "token_env": "GIGA_AGENT_TOKEN"
      },
      "memory": {
        "root": ".",
        "personal": ["AGENTS.md"],
        "knowledge": [".agent-memory/knowledge"]
      }
    }
  ]
}
```

Подставь базовый адрес LangGraph и фактические ID. Если сервер требует
Bearer-токен, укажи имя переменной окружения. Для сервера без авторизации убери
`token_env`. Проверка читает заданные треды. Место, из которого сам GigaAgent
подхватывает готовую память, зависит от его интеграции. [API истории LangGraph](https://docs.langchain.com/langsmith/use-threads#inspect-full-thread-history)

## GigaCode CLI и другие клиенты

Уточни версию и поверхность клиента только когда от них зависит путь. Для
GigaCode CLI можно начать с опубликованных [команд клиента](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/commands).
Если доступен журнал, определи структуру по локальному примеру, сохранив
различие между диалогами, ролями и событиями инструментов. Укажи путь к
поддерживаемому файлу или подготовь нормализованный JSONL.

Если история ещё не сохраняется, проверь документированный режим сохранения
сессии, экспорт, публичный API или хуки клиента. Если пользователь управляет
запуском агента, помоги подключить журналирование через его штатный API или
расширение. Запиши по одному событию на строку в UTF-8. Для всех событий
одного диалога используй один идентификатор сессии. Например:

```jsonl
{"session_id":"demo","id":"1","role":"user","content":"Сохрани проверенный отчёт."}
{"session_id":"demo","id":"2","role":"assistant","content":"Отчёт сохранён."}
```

Проверь запуск командой `setup discover --project <корень> --host <клиент>
--source jsonl --history <файл>`. Если запись проверить нельзя, укажи, какого
доступного источника или механизма клиента не хватает.
